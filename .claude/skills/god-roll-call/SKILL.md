# /roll-call —— 點名、指派暱稱與通訊測試

**開局第一件事。未通過不得進入發牌。**

這一步存在的理由：整場遊戲完全建立在 `SendMessage` 上。若有任何一條線不通，問題會在第三天才浮現，而那時已經無法補救。

**順便把暱稱一次配掉。** 玩家自選暱稱會撞名，撞名就要多跑一輪協調 —— 那一輪不產生任何遊戲資訊，只消耗時間。由上帝在點名時直接指派，這個問題結構上不存在。

### 開始之前，先跟使用者說明為什麼要點名

使用者常會覺得多此一舉 —— 玩家跑完 `/ur` 都向你報到過了，為什麼還要再點一次。

**開始前先講一句，不要等他問：**

```
收到報到，代表玩家端的 SendMessage 正常。
點名是再 double check 一次：確保我發出去的訊息也到得了他們那邊，順便把暱稱發下去。
```

**收到報到＝入站通了；點名驗的是出站。** 兩者不互相保證，
而這個板子真正吃緊的是出站 —— 發牌、夜間行動、指派發言、收票，全部由你發出。

> 講給使用者聽的時候**照上面那個框寫**：說工具正常、說再確認一次、說順便發暱稱。
> **不要用「證明」「充分必要」這類詞** —— 那是規格的語氣，不是主持人的語氣。

## 執行步驟

### 1. 清點在場者

```
ListAgents
```

確認以下 11 個名稱都在列且非 offline：

```
GOD（你自己）  reporter  P1 P2 P3 P4 P5 P6 P7 P8 P9
```

**記下每個 session 的 ref**（例如 `P1 [3998b6]`）—— 之後每階段開始前要比對，ref 變動代表該 session 重啟過。

缺人時：向使用者回報缺哪幾個，**停下來等他建立並改名**，不要自行往下跑。

### 2. 抽暱稱

從下列名單池**隨機抽 9 個**指派給 P1~P9：

```
阿松　白帆　青禾　大河　雨田　山彥　湖心　林間　石頭　風鈴　雲杉　冬陽
```

```python
import random, sys
sys.stdout.reconfigure(encoding='utf-8')
pool = ['阿松','白帆','青禾','大河','雨田','山彥','湖心','林間','石頭','風鈴','雲杉','冬陽']
picked = random.sample(pool, 9)
nicknames = {'P%d' % (i+1): picked[i] for i in range(9)}
print(nicknames)
```

名單池比座位多，所以每一局的組合不同；池子可以增補，但新名字必須符合三個條件：
**與任何身份無關聯、兩字可辨識、彼此不同字**。

> **這裡印出來沒有劇透問題。** 點名發生在洗牌之前 —— 這個時間點上連你自己都還不知道誰是什麼牌，
> 所以座位與暱稱的對應**在結構上不可能攜帶身份資訊**。
> 這也是把指派放在點名而不是發牌的理由之一：發牌時你已經知道底牌了，那時再取名就得自己證明沒有偏袒。

### 3. 並行發送 ping

用 `dispatch ping` 模板，**一個回合內並行發給全部 10 個對象**（9 玩家 + reporter）。
玩家的那 9 則各自帶上他的暱稱；reporter 收的是 `ping_reporter` 模板，沒有暱稱欄。

模板在 `.claude/skills/god-dispatch/references/message-templates.md` 的 `ping` 節。

### 4. 收齊回覆

玩家應回覆「P<n>・<暱稱> 就位」，reporter 回覆「reporter 就位」。

- **全部收齊** → 進第 5 步
- **有缺** → 對缺席者重發一次；仍無回應則向使用者回報是哪幾個、並停下
- **有人回錯暱稱** → 重發一次該則 ping，並在回報中記一筆。**以你指派的為準**，不接受玩家自行更名

### 5. 回報使用者

```
11 個都到齊了，聲音我這邊都聽得到。

九個人的名字發下去了：
P1・○○　P2・○○　…　P9・○○

（各 session 識別碼我記著了，中途誰重開我認得出來。）
```

**有異常就照實講**：誰沒回、誰回錯暱稱、哪一條線不通。
語氣輕鬆，內容不打折 —— 見 `agent-reference/god/04-reporting.md`。

### 6. 建立基準

兩件事：

1. 把 11 個 ref 寫進 `game-state/public/02-status.md` 的「session 基準」區塊。
   往後每階段開始前用 `ListAgents` 比對，ref 變動 → 要求該 session 重跑 `/ur`。
2. **立刻**把座位與暱稱寫進 `game-state/public/00-players.md`（只有這兩欄，此時還沒有身份）。

第 2 項不要拖到 `/god-setup` —— 暱稱只存在你的上下文裡的每一分鐘，都是失憶後
「玩家記得自己叫什麼、你不記得」的風險。寫進檔案就沒有這個問題。

> `02-status.md` 由 `/god-setup` 建立。若此時尚未存在，先把 ref 基準暫記，
> 於 `/god-setup` 第 8 步一併寫入；`00-players.md` 則現在就建，不必等。

### 7. 回報結果，然後直接進開局設定

基準建立完，把事實回報給使用者：

```
點名過了，名單也存好了。接著設定這一局怎麼玩。
```

**然後直接執行 `/god-setup`，不要另外問一次「要不要進行開局設定」。**

那一問是多餘的往返：`/god-setup` 第 1 步本來就會跳出參數卡片，
而那張卡片的第一題就是「要不要現在開局」—— 使用者在**同一次詢問**裡
就能喊停，不需要先被問一次要不要被問。

> **不要在這裡結束回合。** 回報完接著跑 `/god-setup`，
> 見 `agent-reference/god/02-round.md`「什麼時候才可以結束你的回合」。

**未達 11 / 11 就不要往下走**，也不要給上面那段回報 ——
改為列出缺席的是誰、要他處理完再回來。

## 中立性提醒

ping 訊息只做通訊測試與暱稱告知，**不得包含任何遊戲資訊、規則說明或身份暗示**。
模板已經寫死，照渲染即可。

暱稱本身也受這條約束：**名單池裡不得有任何與身份、陣營或技能沾邊的字眼**，
指派必須隨機 —— 不得依座位順序、不得依你對哪個 session 的印象挑選。

## 下一步

點名通過後**直接執行 `/god-setup`**，不要再問一次要不要開局（見第 7 步）。
`/god-setup` 的第 1 步會用一張卡片一次問完四題：開局確認 ＋ 三個開局參數。
使用者要喊停，在那張卡片的第一題選「先不開局」即可。

**發牌訊息不再徵集暱稱** —— 它只複述暱稱，並指派玩家把自介寫進 `public/intro-inbox/`。
