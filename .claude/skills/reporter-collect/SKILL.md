# /reporter-collect —— 併發言逐字稿

## 用法

```bash
python .claude/skills/reporter-collect/collect.py <天數> <輪次> [選項]
```

`<輪次>`：發言輪 `seq`／PK `pk`。

| 選項 | 用途 |
|---|---|
| `--header "<原文>"` | 上帝在併檔指示裡給的那一行（發言順序／發言方式）。**原文照抄** |
| `--expect P2,P3,…` | 上帝給的必讀清單。給了就比對，缺誰會被列出來 |
| `--build` | 併完直接接著產報表，等同再跑一次 `/reporter-build` |
| `--game-dir DIR` | 對局目錄，預設 `game-state` |

**最常用的一行**（上帝的指示裡有順序時）：

```bash
python .claude/skills/reporter-collect/collect.py 2 seq \
       --header "發言順序（隨機起始位 P6，順）：P6 → P7 → …" --build
```

第二位以後就不必再帶 `--header` 了 —— **沒給的時候它會沿用現有逐字稿裡的那一行**。

## 先確認

你已執行過 `/ur reporter`。

## 這支 skill 為什麼存在

發言原本由上帝逐字重打進 `03-speeches-dayN.md`。那是純搬運，卻讓每一則發言
多經過上帝的上下文一次，而且**給了他一個接觸發言內容的機會** ——
上一局的偏袒就是從這種機會裡長出來的。

現在玩家自己寫檔，你負責併。**而併這件事本身也是純搬運，所以交給腳本。**
你負責的是看它有沒有壞掉、以及把它列出來的問題轉給上帝。

## 腳本做了什麼

### 產出兩份，同一份資料

| 檔 | 給誰 |
|---|---|
| `public/03-speeches-day<N>.md` | 給人看、給歸檔、爭議時引用的**權威版本** |
| `public/03-speeches-day<N>.json` | 給 `render.py` 讀 —— 省掉一次 Markdown 解析 |

`render.py` **優先讀 JSON，沒有才解析 Markdown**。`game-archive/` 的歷史對局
沒有 JSON，所以那條路徑永遠留著，舊局照樣畫得出來。

### 整份重生成，不是追加

每位落檔後都會跑一次，同一份檔會被處理很多次。腳本**每次都從 inbox 重新生成整份**，
所以「同一位重複跑不會產生第二份」是結構上保證的，不需要你先讀現有內容確認誰已經在裡面。

> 這順帶消掉了一整類錯誤：追加式寫法一旦把非發言內容接在檔尾，那段會被併進
> **最後一則發言的內文**，而則數仍然正確 —— 計數檢查在原理上抓不到它。

### 排列順序

`seq` 依上帝給的那一行裡出現的座位順序；`--header` 沒給就沿用現有檔裡的那一行；
兩者都沒有才照座位號。**PK 一律依座位號。**

**腳本不會自己推斷順序** —— 你看到的落檔先後不等於上帝公告的順序。

### 它會替你檢查的事

- 超過 **400 字**的發言（正文不含空白換行，最後那行 `【宣告】` 不計入）
- 沒寫身份宣告的人
- 同一位在同一輪有兩份檔
- 檔名不合規則、內容是空的
- `--expect` 給了的話：必讀清單與 inbox 對不上

**沒有問題時它會說「沒有要回報上帝的事」。**

## 三條紀律（腳本遵守，你也要）

- **純字串搬運。** 不改寫、不修錯字、不調整段落、不歸納。玩家寫什麼就是什麼。
  **超長的照原文併進去，一個字都不刪** —— 刪節是對發言的改寫。
- **宣告漏填就是漏填。** 標題寫成 `【宣告：未填】`，回報上帝由他補問。
  **絕對不要替他判讀** —— 從發言內容推斷他跳了什麼是對發言的解讀，那是上帝與你都不做的事。
- **填了列舉以外的值就照抄。** 腳本只搬運玩家原本寫了什麼，
  正規化（那個封閉列舉）留在 `render.py` 的 `CLAIM_TOKENS` 一處，不合法的值會靜默降級。
  **兩處各存一份列舉就是等著漂移，所以刻意只有一份。**

> 正文最後那一行 `【宣告】<值>` **會保留在內文裡**，不會因為抄進標題就被拿掉。
> 正文是權威來源，標題只是索引。

## 不要回報，除非出事

**併完不用回上帝。** 他送出指派後就往下走了，你的「收到」「已完成」只會打斷他的流程 ——
發言輪一天有 9 則指派，9 則回覆就是 9 次打斷。

腳本印出「要回報上帝的 N 項」時，**把那幾行轉給他就好**，不必加話。
另外這一項腳本判不了，要你自己看：

| 情況 | 為什麼要說 |
|---|---|
| `/reporter-verify` 沒過 | 紀錄本身壞了，繼續推進會讓錯誤擴散到後面每一天 |

其餘一切正常就安靜做完。**沉默即正常**，這是上帝那邊的預期。

## 落後了怎麼辦

你可能同時收到好幾則併檔指派。**不要逐則跑** —— 因為是整份重生成，
直接跑最後一次就會把該天所有已落檔的檔案都收進去，前面那幾則不必補跑。

**併檔落後不影響對局**：玩家讀的是 inbox 原文，不是你的產出。
你的產出服務的是報表、歸檔與爭議時的引用。

## 接著畫圖

帶 `--build` 就併完直接產報表（發言本來就是公開的，不加 `spoiler`）。
沒帶的話自己跑 `/reporter-build`。
