# /reporter-build —— 產出戰況報表

## 先確認

你已執行過 `/ur reporter`。若沒有，先跑它 —— 否則 hook 會擋下你對
`game-state/secret/` 的存取（那是機制，不是錯誤）。

## 步驟

1. **先跑 `/reporter-verify`。** 檢查沒過就不要畫，先通報上帝。
2. 執行渲染腳本。**看上帝有沒有給你 `spoiler` 這個參數：**

**沒給（兩份都產）** —— 天亮公告後、發言輪每一位落檔後、
票型公布後、PK 唱票後、投票結算、終局戰報與 MVP 之後：

```
python .claude/skills/reporter-build/render.py
```

**給了 `spoiler`（只產劇透版）** —— 夜間收尾、勝負達成的當下：

```
python .claude/skills/reporter-build/render.py game-state --spoiler-only
```

   （要重建某一局的歸檔報表，把目錄當參數傳進去：
   `python .claude/skills/reporter-build/render.py game-archive/001-20260904`）

### 為什麼有兩種模式

公開版 `report/index.html` **玩家讀得到**，而它會把死者標成 X；勝負已定時還會列出全員底牌。
夜間收尾與勝負達成的那兩個時刻，結果都還沒有被上帝公告出去 ——
這時產公開版，等於搶在上帝之前向全場公布死訊或底牌。

**所以參數帶不帶，是資訊會不會提早外洩的差別，不是效率問題。上帝給了就照給的跑。**
不確定時問上帝，不要自己決定。

3. 讀腳本的輸出。**防劇透掃描命中時它不會產生公開版**，會列出命中位置 —— 修掉來源再跑一次。
4. 打開產出的 HTML 檢查版面沒有明顯破損。
5. **在你自己的對話輸出印出產出路徑** —— 見下方「每次都要印路徑」。
6. 回報上帝。

## 每次都要印路徑

跑完之後，**在你自己的正文輸出**（不是只放進給上帝的 `SendMessage`）印出這兩行：

```
公開版　game-state/report/index.html
劇透版　game-state/secret/report-spoiler.html
```

只產劇透版時（帶 `spoiler` 參數）就只印劇透版那一行，**不要印一條不存在的路徑**。
重建歸檔對局時印該局目錄底下的實際路徑
（`game-archive/NNN-日期/report/index.html`、`.../god-view/report-spoiler.html`）。

**為什麼要獨立做這件事**：給上帝的 `SendMessage` 不會出現在人類觀戰者的畫面上，
而腳本印的那兩行混在工具輸出裡。人類要的是**在你的對話框裡可以直接點開的連結** ——
寫成專案根目錄起算的相對路徑就會是可點的。

**路徑照抄腳本輸出的那兩行**，不要自己拼字串 —— 拼錯的路徑點不開，
而且看起來跟對的一模一樣。

## 你會被叫得很頻繁，這是正常的

觸發點對齊的是**檔案落地的時刻**，不是回合。`render.py` 的輸入只有六個檔：

```
public/00-players.md   public/03-speeches-dayN.md   public/04-votes-dayN.md
secret/roles.json      secret/potions.json          secret/nightlog.json
```

其中 `03-speeches-dayN.md` 在發言輪會反覆追加：每位發言後追加一次，
一天約 9 則通知，由上帝的 subagent 送出（送完就結束，不等你回覆）。

**每則都照跑，不要合併、不要跳過** —— 合併就等於自己決定觀戰者哪幾位的發言
不值得即時看到，那不是你的判斷範圍。

歷史歸檔的逐字稿可能帶著 `## 第 N 輪` 這類標題（舊局留下的格式），
`render.py` 讀到時仍會據此分輪呈現；現行的發言輪不會產生這種標題，
整份逐字稿就是一組，輸出照常。

> `01-timeline.md`、`02-status.md`、`99-reveal.md`、`99-audit.md`、`99-mvp.md`
> **都不是 `render.py` 的輸入**。上帝寫這些檔的時刻不會單獨觸發你。

## 為什麼用腳本而不是手寫 HTML

報表一局要重建十幾次。**手寫每次都會漂移** —— 版面、欄位、用詞都會慢慢變，
而你很難察覺自己這次少放了什麼。腳本是確定性的：同樣的資料永遠產生同樣的報表，
你只要負責看它有沒有壞掉。

版面要改就**改腳本**（對所有後續一致生效），不要這一次手動補幾行。
這與上帝的 `/god-dispatch` 用固定模板是同一個道理。

完整的版面規格、兩份報表各放什麼、技術要求 → `agent-reference/reporter/02-render.md`。

## 防劇透掃描（**不可略過**）

對**公開版**執行：

```
P[1-9] 前後 14 個字元內出現以下任一字樣即為命中：
狼人／預言家／女巫／獵人／平民／村民／查驗／毒藥／解藥

必須 0 命中。腳本會自動執行，命中就拒絕產生公開版。
```

**掃描範圍不含逐字引用區。** 玩家的發言與投票理由本來就充滿「預言家」「狼」
這些字眼，而那些是**已經公開的原文** —— 對它們掃描只會產生假陽性。
腳本用 `<!--QUOTE-->` 標記把所有逐字取自公開檔的內容排除在掃描之外。

判準是：**這段字是 reporter 生成的，還是從公開檔原樣抄來的？**
只有前者需要掃描。

> 上一局就是因為訊息模板的範例寫了真實座位號，把一個身份洩漏出去。
> **人的注意力會漏，掃描不會。**

## 兩條硬規則

1. **公開版的資訊界線 ＝ 玩家讀得到的界線。** 判準：如果一個玩家不該知道，它就不該在公開版裡。
2. **這支 skill 只新增你自己的兩份 HTML**，不修改 `public/` 或 `secret/` 底下任何既有檔案。
   （開局的 `/reporter-init` 會建立狀態檔，那是另一支 skill 的一次性例外；
   改寫別人已經寫好的內容，任何時候都不可以。）

## 回覆格式

```
報表已更新：第 N 天・<階段>
公開版：game-state/report/index.html
劇透版：game-state/secret/report-spoiler.html
一致性檢查：7/7 通過
防劇透掃描：0 命中
```

檢查未通過時，把未過的項目與**具體數字**寫在這裡，不要只說「有問題」。

> 這是給**上帝**的 `SendMessage`。路徑在你**自己的正文**也要印一次 ——
> 見上方「每次都要印路徑」。兩邊都要，不是二選一。
