# /reporter-build —— 產出戰況報表

## 先確認

你已執行過 `/join-as reporter`。若沒有，先跑它 —— 否則 hook 會擋下你對
`game-state/secret/` 的存取（那是機制，不是錯誤）。

## 步驟

1. **先跑 `/reporter-verify`。** 檢查沒過就不要畫，先通報上帝。
2. 執行渲染腳本：

```
python .claude/skills/reporter-build/render.py
```

   （要重建某一局的歸檔報表，把目錄當參數傳進去：
   `python .claude/skills/reporter-build/render.py game-archive/001-20260904`）

3. 讀腳本的輸出。**防劇透掃描命中時它不會產生公開版**，會列出命中位置 —— 修掉來源再跑一次。
4. 打開產出的 HTML 檢查版面沒有明顯破損。
5. 回報上帝。

## 為什麼用腳本而不是手寫 HTML

報表一局要重建十幾次。**手寫每次都會漂移** —— 版面、欄位、用詞都會慢慢變，
而你很難察覺自己這次少放了什麼。腳本是確定性的：同樣的資料永遠產生同樣的報表，
你只要負責看它有沒有壞掉。

版面要改就**改腳本**（對所有後續一致生效），不要這一次手動補幾行。
這與上帝的 `/god-dispatch` 用固定模板是同一個道理。

完整的版面規格、兩份報表各放什麼、技術要求 → `agent-reference/reporter/workflow-render.md`。

## 防劇透掃描（**不可略過**）

對**公開版**執行：

```
P[1-9] 前後 14 個字元內出現以下任一字樣即為命中：
狼人／預言家／女巫／獵人／平民／村民／查驗／毒藥／解藥

必須 0 命中。腳本會自動執行，命中就拒絕產生公開版。
```

**掃描範圍不含逐字引用區。** 玩家的發言與投票理由本來就充滿「預言家」「狼」
這些字眼，而那些是**已經公開的原文** —— 對它們掃描只會產生假陽性。
腳本用 `<!--QUOTE-->` 標記把所有逐字取自公開檔的內容排除在掃描之外。

判準是：**這段字是 reporter 生成的，還是從公開檔原樣抄來的？**
只有前者需要掃描。

> 上一局就是因為訊息模板的範例寫了真實座位號，把一個身份洩漏出去。
> **人的注意力會漏，掃描不會。**

## 兩條硬規則

1. **公開版的資訊界線 ＝ 玩家讀得到的界線。** 判準：如果一個玩家不該知道，它就不該在公開版裡。
2. **只新增你自己的兩份 HTML**，不修改 `public/` 或 `secret/` 底下任何既有檔案。

## 回覆格式

```
報表已更新：第 N 天・<階段>
公開版：game-state/report/index.html
劇透版：game-state/secret/report-spoiler.html
一致性檢查：7/7 通過
防劇透掃描：0 命中
```

檢查未通過時，把未過的項目與**具體數字**寫在這裡，不要只說「有問題」。
