# /god-resume —— 失憶復原

## 什麼時候用

- 你的 session 重啟過
- 上下文被壓縮，你不確定現在是第幾天、誰還活著、下一步該做什麼
- reporter 通報你紀錄有不一致，而你不記得為什麼

**不要憑印象接續。** 檔案是唯一真相來源，你的記憶只是快取。

## 復原順序

### 1. 重新載入角色

`/ur god`

### 2. 讀公開狀態（最關鍵的一步）

```
game-state/public/02-status.md
```

它記載：**天數、當前階段、存活名單、死亡名單、剛完成什麼、下一步要做什麼、session ref 基準**。

**整個復原機制就靠這個檔案。** 如果它不存在或過期，代表前一個你沒有遵守「每階段更新」的規則 —— 那就從 `01-timeline.md` 重建。

### 3. 取回上帝視角

直接讀 `game-state/secret/` 的三份 JSON：

```
secret/roles.json     座位對應身份、存活名單
secret/potions.json   藥水、獵人開槍、天數、階段、勝負判定
secret/nightlog.json  nights 陣列 + day_votes 陣列
```

讀得到是因為你的 session 登記為 `god`。**若被 hook 擋下**，表示 `/ur god`
沒有正常登記 —— 請使用者確認 `game-state/public/roster.json` 的 `god` 是不是你這個 session
（session 重啟會換 id，使用者可以直接編輯那個檔案）。

### 3.5 請 reporter 驗一次

`/reporter-verify`。**失憶後最危險的不是不知道，是記錯了還照著做。**
七項檢查會告訴你紀錄本身有沒有在你失憶期間被弄壞。

### 4. 補脈絡

需要時讀：
- `01-timeline.md` —— 公開播報流水帳
- `03-speeches-dayN.md` —— 當天發言逐字稿
- `04-votes-dayN.md` —— 票型與所有理由

### 5. 檢查玩家 session

用 `ListAgents` 比對 11 個 ref 與 `02-status.md` 的基準。
**任何變動的 session 都要求它重跑 `/ur`**，並補發它原本持有的資訊。

### 6. 接續

從 `02-status.md` 記載的「下一步」開始，呼叫對應的 skill。

## 玩家重啟時你要做的事

玩家會主動告訴你它重啟了並請求補發。你應該：

1. 補發它的身份牌、專屬識別碼、以及**它自己的行動歷史**（它說過什麼、投給誰、被誰指控）
2. **只還原它原本就持有的資訊，不給任何額外優勢**
3. 爭議發生時**把公開檔路徑給它，讓它自己查證** —— 不要替它複述結論

> 上一局有玩家重啟後指出我補發的內容有誤。查證後錯的是它（它只比對發言逐字稿，漏掉投票理由也是公開紀錄）。**正確做法是給路徑不給結論** —— 這既符合中立性，也讓對方自己發現真相。
