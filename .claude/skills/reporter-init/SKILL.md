# /reporter-init —— 開局初始化

## 先確認

- 你已執行過 `/ur reporter`
- `game-state/secret/roles.json` **已經存在** —— 那是上帝洗牌時寫的底牌，你只讀不寫
- `game-state/public/00-players.md` 與 `02-status.md` 已經存在（上帝在發牌前就寫好了）

任何一項不成立 → **停下來回報上帝**，不要自己補。

## 你做三件事，然後回報一次

上帝會在發牌的同時指派你，所以這支 skill 與他的發牌是**並行**跑的。
他收齊九份回覆、廣播完名冊之後會來收你的回報，**那是他進第一夜的閘門**。

---

## 一、建檔

`roles.json` 不在裡面 —— **底牌是上帝寫的，你只讀。**

| 檔案 | 內容 |
|---|---|
| `secret/potions.json` | 兩瓶藥未使用、獵人未開槍、`alive` 9、`dead` 空、`day` 0、`phase`、**`"result": null`** |
| `secret/nightlog.json` | `{"nights": [], "day_votes": []}` —— 累積式容器，之後只追加 |
| `public/01-timeline.md` | 開局初始內容（第 0 天、發牌完成） |
| `public/HOSTING-PROCEDURE/` | **目錄**，把 `.claude/rules/` 六份原樣複製進去：<br>`board.md`／`conduct.md`／`flow.md`／`glossary.md`／`god-neutrality.md`／`messaging.md` |

**`alive` 與座位一律從 `secret/roles.json` 讀出來，不要自己編。**
你手上那份才是權威，憑印象重打就是在製造第二個真相。

不需要加解密，`secret/` 由 hook 保護。

### `result` 是硬檢查

`potions.json` 的 `"result"` **必須是 `null`**。

它是 `render.py` 判斷公開版要不要揭底牌的**唯一開關** ——
一有值，公開版就會列出全員身份並跳過防劇透掃描。
**開局就寫錯，等於第一分鐘把九個人的底牌貼在公開報表上。**

所以不是「記得寫 `null`」，是**建完立刻讀回來確認它是 `null`**。
不是 → 停下、不要產報表、回報上帝。

> 它形如 `{"winner": "好人|狼人", "reason": "屠邊（平民全滅）", "day": 3}`，
> 但那是勝負真的達成時上帝才寫的，不是你的事。

## 二、開局驗證（五項）

| # | 檢查 | 判準 |
|---|---|---|
| 1 | 三份狀態檔就位 | `roles.json`／`potions.json`／`nightlog.json` 存在且可讀，`nights` 與 `day_votes` **兩個陣列都是空的** |
| 2 | **`result` 是 `null`** | 見上面的硬檢查 |
| 3 | 存活名單三處一致 | `02-status.md`、`roles.json.alive`、`potions.json.alive` 完全相同，都是 9 人 |
| 4 | 座位表與底牌一致 | `00-players.md` 的九個座位與 `roles.json` 的 `seats` 完全相同（**只比座位，不看身份**） |
| 5 | 防劇透掃描零命中 | `render.py` 產公開版時已內建 |

### 為什麼不是跑 `/reporter-verify` 要 7/7

那七項裡的**第 5 項（每日票數）與第 6 項（發言人數）在開局無檔可驗** ——
還沒有任何一天的投票或發言。要求 7/7 在開局是不可能達成的。

上面五項是它適用的部分（#2 存活三處一致、#3 nightlog 空容器）加上 `result`
硬檢查與座位表比對後的開局版本。角色數那一項由上帝自己驗 —— 牌是他洗的，
**他手上有第一手資料，那比你讀檔案更有效力**。

### 「狀態的下一步」不在你這裡，這是刻意的

你與上帝的發牌是**並行**跑的。他要到收齊九份回覆、廣播完名冊（他的第 9 步）
才有資格把 `02-status.md` 的「下一步」改成「第 1 夜」——
**你在他寫之前去讀，讀到的必然是舊值。** 那不是矛盾，是你到得太早。

所以那一項改由上帝在他的第 10 步自驗：走到哪一步是他的第一手資料。
你換成驗座位表 —— 那份檔在你開工前就寫好了，不會在你腳下變動。

從第 1 天起 `/reporter-verify` 的第 7 項照常驗「狀態不與最新事件矛盾」，
**那時候寫檔與驗檔是前後順序，不並行**，所以驗得準。

`/reporter-verify` 本身不變，從第一天起照常每次產報表前跑。

## 三、產報表

等同 `/reporter-build`（不加 `spoiler`，兩份都產）。

```
python .claude/skills/reporter-build/render.py
```

驗證沒過就**不要產** —— 錯誤資料畫成圖表只會更有說服力。

---

## 回報上帝一次

**這一則是例外。** 你平常的紀律是「沉默即正常、只在出事時出聲」，
但這一則不同 —— **上帝拿它當進第一夜的閘門**，你不回報他就停在那裡。

格式固定，讓他能確定性解析：

```
開局初始化完成
開局驗證：5/5 通過
報表：game-state/report/index.html / game-state/secret/report-spoiler.html
```

未通過時：

```
開局初始化中止
開局驗證：N/5 通過

未通過：
- 第 <編號> 項<名稱>
  <來源 A> = <數值>
  <來源 B> = <數值>
  推測原因：<一句話>
```

**發現不一致時不要自己修**（除了你自己剛建的那幾個檔）。
先排除無害解釋 —— 編碼差異、CRLF/LF、空白。

## 一局只跑一次

這支 skill 只在開局跑。之後的每一個落檔點都是 `/reporter-build`，
時機表在 `.claude/agents/reporter.md`。

檔案已經存在就**不要覆寫** —— 那代表這一局已經初始化過了，回報上帝讓他判斷。
