# /reporter-verify —— 結構稽核

## 先確認

你已執行過 `/join-as reporter`。

## 七項檢查

| # | 檢查 | 判準 |
|---|---|---|
| 1 | 角色數恆定 | `roles.json` 恆為 3 狼 / 3 民 / 1 預 / 1 巫 / 1 獵，共 9 席 |
| 2 | 存活名單三處一致 | `02-status.md`、`roles.json`、`potions.json` 完全相同 |
| 3 | **nightlog 只增不減** | `nights` 與 `day_votes` 陣列長度只能增加或持平 |
| 4 | 死亡人數對得上 | `9 − 存活人數` ＝ 時間軸公布過的死亡總數 |
| 5 | 每日票數不超過存活人數 | 含棄票的總票數 ≤ 該日存活人數 |
| 6 | 發言人數相符 | 發言者集合 ＝ 該日存活名單（缺席須對應到逾時紀錄） |
| 7 | 狀態不與最新事件矛盾 | `02-status.md` 的「下一步」與已存在的檔案不衝突 |

每一項的理由與細節 → `agent-reference/reporter/workflow-verify.md`。

**第 3 項最重要** —— 上一局上帝每晚整份覆寫 `nightlog`，吃掉了前兩夜的紀錄。

## 發現不一致時

1. **不要自己修。** 你不是紀錄的擁有者。
2. **不要繼續產報表。** 錯誤資料畫成圖表只會更有說服力。
3. 通報上帝，**給具體數字**，並先排除無害解釋（編碼差異、CRLF/LF、空白）。

## 回覆格式

```
一致性檢查：N/7 通過

未通過：
- 第 <編號> 項<名稱>
  <來源 A> = <數值>
  <來源 B> = <數值>
  推測原因：<一句話>
```

全部通過時：

```
一致性檢查：7/7 通過
基準：nights=<n>、day_votes=<n>、存活=<n>
```
