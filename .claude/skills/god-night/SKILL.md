# /god-night —— 天黑

## 開始前

用 `ListAgents` 比對各 session 的 ref 與 `02-status.md` 的基準。
**ref 變動 → 該 session 重啟過 → 要求它重跑 `/ur`，並補發它原本持有的資訊**（只還原它本來就該有的，不給額外優勢）。

## ⚠ 回報節奏：第 2 夜起三階段一次跑完

**階段的有無本身就是情報。** 預言家死後若逐階段回報，「今晚沒有查驗階段」就洩漏了他已出局。

- 第 1 夜：可依使用者的節奏參數逐階段回報
- **第 2 夜起：三階段全部跑完才回報**，並向使用者說明這是刻意合併

## 階段 1・狼人行動（隊長制，四步）

### 先確定今晚的隊長

- **第 1 夜**：從三隻狼中**隨機**選一位。不要依座位順序、不要依你對哪個 session 的印象挑。
- **之後每夜**：沿用昨夜的隊長；**隊長已出局**則依他昨夜提交的接班順位，取第一位存活者。
  順位裡的人也都死光 → 從存活狼人中重新隨機指定。
- 只剩一隻狼 → 他就是隊長。

### 四步

1. `/god-dispatch night_wolf_open` —— **並行**發給所有存活狼人，告知誰是隊長。
   非隊長的提交暗號，隊長等你轉達。
2. 收齊暗號 → `/god-dispatch night_wolf_relay` **單點**發給隊長。
   **具名、原文、依座位號排序**，逾時未交的標為「（未提交）」。
3. 收隊長的決定：
   - **必填**：刀誰（可自刀）、接班順位
   - **選填**：悍跳／陪跳／倒鉤／深水
4. `/god-dispatch night_wolf_plan` —— **並行**轉達給其他狼，不需回覆。

### 只剩一隻狼時

他就是隊長，四步縮成兩步：

- 第 1 步照發（`role_instruction` 用隊長版），**沒有暗號要收**
- 第 2 步照發，但把隊友暗號區塊整段省略
- **第 4 步整個跳過** —— 沒有其他狼可以轉達
- **接班順位填「無」** —— 沒有人可以接，這一項不算漏填，不要補問

### 仲裁

- 隊長的決定**直接成立**，不需要其他狼同意，也沒有第二輪。
- 非隊長逾時 → 棄權，照常進行。
- 隊長逾時 → 重發一次；再逾時 → 由接班順位第一位代為決定。
- 全員逾時 → 你**隨機**裁決刀人目標。
- 隊長漏填接班順位 → 補問**那一項**；仍未給則預設為存活狼人座位號由小到大，
  並在 nightlog 標記 `"succession_default": true`。
- **空刀不成立** —— 每晚必定產生一個目標。

### 三條紀律

- **暗號只搬表內的。** 不在暗號表內的內容一律不轉達，也不要退回去問他是什麼意思
  —— 猜測玩家的意思就是替他發言。
- **分工留空是合法的提交。** 不要追問「還沒指派悍跳」，那是在暗示他應該指派。
- **不要摘要暗號。** 不排序成「多數意見」、不統計、不加評語 —— 原文照搬，
  跟逐字稿的規矩一樣。

## 階段 2・預言家查驗

存活的預言家才有這一步。

1. `/god-dispatch night_seer`
2. 收到指定對象 → 查底牌 → `/god-dispatch night_seer_result` 回覆**陣營**（好人／狼人），不含具體身份
3. 逾時視為**空過**

**預言家已死時，靜默跳過，不要向任何人提及這個階段。**

## 階段 3・女巫用藥

存活的女巫才有這一步。

1. `/god-dispatch night_witch` —— 明確告知**今晚被刀者**與**兩瓶藥的剩餘狀態**
2. 收到決定：解藥救人／毒藥毒人／都不用
3. **同晚不可雙開**；解藥只能救當晚被刀者
4. 逾時視為不用藥

## 結算

1. 合併死亡名單（狼刀 + 毒殺，扣除被解藥救回者）
2. **檢查死者中是否有獵人** —— 有的話先 `/god-dispatch hunter_shot` 單獨詢問開槍對象，結算後才進天亮
   - **被女巫毒死的獵人不能開槍**
3. 更新存活名單

## 收尾（四件）

寫檔的時機與判準見 `agent-reference/god/03-recordkeeping.md`。

1. 把本夜行動**追加**進 `secret/nightlog.json` 的 `nights` 陣列
   —— **累積式，讀出來、加一筆、寫回去。絕對不可以用單夜資料整份覆寫。**
   上一局就是這樣吃掉了前兩夜的紀錄。
2. 更新 `secret/potions.json`（藥水、獵人開槍、存活/死亡名單、天數、階段）
3. 更新 `public/02-status.md`（天數、存活、剛完成什麼、**下一步**）與 `01-timeline.md`
4. **通知 reporter 重建報表 —— 只產劇透版**：

   ```
   SendMessage → reporter
   「第 N 夜已結算，請執行 /reporter-build spoiler。」
   ```

   **`spoiler` 這個參數不可以省略。** 公開版報表會把死者標成 X，而昨夜的結果
   此刻還沒公告出去 —— 少打這兩個字，等於在天亮之前先向全場公布誰死了。
   死者若是獵人更嚴重：規則要求先私下問完開槍對象才公布名單。

> `secret/` 由 hook 保護，你讀寫得到是因為你的 session 登記為 god。
> **不需要任何加解密步驟** —— 直接讀寫 JSON。

## 向使用者回報

依播報風格參數。**只播報公開資訊** —— 夜間行動一律以「夜色中發生了些什麼」帶過，不透露誰刀誰、誰查誰。
