# /god-audit —— 稽核

完整規格：`references/audit-spec.md`

## 什麼時候跑

**只有兩個時機：終局（`/god-endgame` 的全場稽核），以及出現可疑跡象時**
（見 `agent-reference/god/06-incident.md`）。

**不再每夜跑。** 每夜稽核一整場 transcript 太慢，把對局節奏拖垮了 ——
而 hook 是即時攔截的：每一次被擋下的嘗試當下就寫進 `.claude/hooks/access.log`，
不會因為稽核晚一點做就消失。**證據是累積的，稽核只是去讀它。**

## 職責切分

- **reporter 做結構稽核**：紀錄的內部一致性 —— 內建在 `/reporter-verify`
- **hook 做即時攔截**：`.claude/hooks/access.log` 記錄每一次被擋下的存取嘗試
- **你做行為稽核**：掃玩家 transcript 的工具呼叫。你本來就知道全部真相，讀 transcript 不增加你的資訊優勢

## A. 玩家行為稽核

transcript 目錄由專案路徑推算，不寫死：

```bash
python .claude/skills/god-audit/transcript_dir.py
```

掃它印出的目錄底下 `*.jsonl` 中每位玩家的 `tool_use`：

| 檢查項 | 判定 |
|---|---|
| 參數含 `.jsonl` | 讀取 transcript → 違規 |
| 參數含 `game-state[\/]secret` | 存取機密檔 → 違規 |
| 參數含 `agent-memory[\/](god\|reporter)` | 讀取不屬於自己的記憶 → 違規 |
| `SendMessage` 的 `to` 非 GOD | 玩家間直接通訊 → 違規 |
| 出現不屬於自己的浮水印 | **違規實證，且可反查來源** |

### 白名單（不得誤報）

開局為取得位址呼叫 `ListAgents`、讀 `game-state/public/`、讀 `.claude/rules/` 與屬於自己角色的 reference、session 重啟後讀 `MEMORY.md` 及其索引指向的檔案。

### 三個實測踩過的假陽性

1. **`uds:` 開頭的位址就是你自己的位址** —— 玩家回覆時複製 `from` 欄位。當成「非 GOD」會**誤報全場九人違規**。
2. **base64 密文會偶然含座位字串** —— 判斷外洩要看**帶引號與冒號的明文結構**，不是裸字串。
3. **重啟後讀 `memory/` 是標準脈絡回復** —— 先看時間戳。

> **命中數不是證據，命中的上下文才是。** 上一局若照單全收 grep 結果，會產出至少三個不存在的違規事件。

## B. 你自己的中立性稽核

掃你**這一局**發給玩家的所有訊息：

**禁用詞命中須為 0**
```
參考思路  值得思考  供你權衡  可以思考的點  你需要處理
建議你    常見打法  供你判斷  幾個可以思考  你的處境
```

**還要確認**
- 轉貼的逐字稿與 `public/03-speeches-dayN.md` **逐字相同**（禁止摘要）
- 每一段都能對應 `rules/god-neutrality.md` 白名單的六類之一
- 沒有形容詞化的轉述（「他直接對你喊話」「最鋒利的一擊」）

**違規時**：向使用者揭露 → 在公開紀錄中記載 → 修正模板。**不要私下算了。**

> 這一段以前每階段跑一次，現在併進終局一次做完。
> 訊息一律從 `god-dispatch` 的模板渲染，偏袒沒有夾帶的縫隙 ——
> **靠的是模板，不是靠每階段自查。**

## C. 交叉驗證（用既有資料，不新增機制）

- 玩家對玩家訊息總數應為 **0**（集中式抿牌後玩家不互通）
- 票數總和 = 存活人數
- 角色數恆為 3 狼／3 民／1 預言家／1 女巫／1 獵人
- 死亡名單與夜間紀錄一致

## D. 回報

乾淨就一行「n/n 清白」；有異常則附**玩家、工具、參數原文與複查結論**。

**永遠不要宣稱「保證沒有作弊」**，只提供稽核結果讓使用者自己判斷可信度。
