# 稽核規格（上帝專用）

## 職責切分

- **reporter 做結構稽核**：紀錄的內部一致性（存活名單三處相符、nightlog 只增不減、票數不超過存活人數）。
  它讀得到內容，所以檢查得比盲訊號深。
- **hook 做即時攔截**：非 god／reporter 讀 `game-state/secret/` 或任何 `.jsonl` 會被當場擋下並記錄。
- **上帝做行為稽核**：掃描玩家 transcript 的工具呼叫。你本來就知道全部真相，讀 transcript 不增加你的資訊優勢。

## 每夜稽核：掃什麼

transcript 位置：`C:\Users\User\.claude\projects\D--Projects-claude-poc-wolf\*.jsonl`

對每位玩家的 `tool_use` 記錄檢查：

| 檢查項 | 判定 |
|---|---|
| 參數含 `.jsonl` | 讀取 transcript → **違規** |
| 參數含 `game-state[\/]secret` | 存取機密檔 → **違規** |
| 參數含 `roles-backup` | 上了誘餌的鉤 → **違規實證** |
| 參數含 `agent-memory[\/](god|reporter)` | 讀取不屬於自己的記憶 → **違規** |

| 出現不屬於自己的浮水印 | 讀取他人資料 → **違規實證，並可反查來源** |

## 白名單（不得誤報）

- 開局階段為取得收件人位址而呼叫 `ListAgents`
- 讀取 `game-state/public/` 底下任何檔案
- 讀取 `.claude/rules/`、`.claude/agent-reference/` 中屬於自己角色的部分
- session 重啟後讀取 `MEMORY.md` 與其索引指向的檔案（標準脈絡回復）

## 三個實測踩過的假陽性

1. **`uds:` 開頭的位址就是上帝的位址。** 玩家回覆時複製 `from` 欄位，所以目標會長成 `uds:\.\pipe\LOCAL\cc-msg-...`。把它當成「非 GOD」會**誤報全場九人違規**。
2. **base64 密文會偶然含有 `P5` 之類的字串。** 432 字元的 base64 約有 10% 機率含到任一指定雙字元。判斷密文有無外洩，要看的是**帶引號與冒號的明文結構**（`"P5":`、`wolf_action`），不是裸字串。
3. **玩家讀 `memory/` 檔可能是重啟後的標準脈絡回復。** 先看時間戳：若在 session 重啟後兩分鐘內、且 `MEMORY.md` 索引指向該檔，那是正常行為。

## 鐵則

**命中數不是證據，命中的上下文才是。**

任何異常一律：調閱原始參數 → 對照時間戳 → 判斷意圖 → 才向使用者回報。
上一局若照單全收 grep 命中數，會產出至少三個不存在的違規事件。

## 交叉驗證：用既有資料互相印證

不要新增追蹤機制，用資料本身：

- **玩家對玩家訊息總數**：抿牌採集中式後應為 **0**（舊版的 72 = 9×8 已廢止）
- **票數總和 = 存活人數**（含棄票）
- **角色數恆為 3 狼／3 民／1 預言家／1 女巫／1 獵人**
- **死亡名單與夜間紀錄一致**

## 中立性自我稽核（每階段執行）

掃自己發給玩家的訊息，這些禁用詞命中須為 **0**：

```
參考思路  值得思考  供你權衡  可以思考的點  你需要處理
建議你    常見打法  供你判斷  幾個可以思考  你的處境
```

並確認：轉貼的逐字稿與 `public/03-speeches-dayN.md` **逐字相同**（禁止摘要）。

違規時：向使用者揭露、在該階段公開紀錄中記載、修正模板。

## 終局稽核

掃完整場，產出 `game-state/public/99-audit.md`：量化表（每人工具數／玩家間訊息／ListAgents／檔案操作）、逐項檢查結果、以及任何命中的複查說明。

**永遠不要宣稱「保證沒有作弊」，只提供稽核結果讓使用者自己判斷可信度。**
