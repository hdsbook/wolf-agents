# 播報者的教訓（追加式）

**這個檔案只寫跨局的方法論與純數字基準。絕不寫任何一局的底牌或當局狀態。**

> 保護機制會改（上一局靠加密，這一局靠 hook），但寫進檔案的東西會留很久。
> **不要讓紀律依賴當下的機制。**

**新增教訓**：在 `lessons/` 新增一檔，四欄格式（結論／原因／來源／怎麼用），並在本索引加一行。

---

- [L28・追加式併檔對「事後改寫」是無感的](lessons/L28-追加式併檔對事後改寫.md) — 併檔改成以 inbox 現檔整份重建，不要用追加。
- [L29・字數超標要當成「可能是快照」而不是「違規事實」](lessons/L29-字數超標要當成可能是.md) — 回報超標時把數字與計法一起講清楚，並註明以對方核對的現檔為準，不要用違規的語氣定調。

## 基準表（只記數字）

| 時點 | nights | day_votes |
|---|---|---|
| 開局 | 0 | 0 |
| 第 1 夜結算 | 1 | 0 |

- [L30・驗不到東西的檢查會顯示「通過」](lessons/L30-驗不到東西的檢查會顯.md) — 每條計數型檢查都要同時印出它數到的原始數量，不要只印通過與否。
- [L31・三處一致的欄位，只會被改到其中兩處](lessons/L31-三處一致的欄位只會被.md) — 這條檢查在本局第一次抓到真錯誤，價值已經證明，永遠不要跳過它。
- [L32・上帝的更新通知會如實列出他改了哪些檔，那份清單就是線索](lessons/L32-上帝的更新通知會如實.md) — 拿他列出的清單去對照你已知「存著同一份事實的所有檔案」，差集就是最可能出錯的地方。
- [L33・一致性檢查的基準要綁在「事件當時」，不是「現在」](lessons/L33-一致性檢查的基準要綁.md) — 從 nightlog 逐夜逐日累積推算該時點的存活數：該日白天存活 = 9 − 第 1..N 夜死亡 − 第 1..N-1 天出局。
- [L34・欄位名沒對上時，錯誤的形狀是「零」而不是「例外」](lessons/L34-欄位名沒對上時錯誤的.md) — 寫任何「從結構化紀錄抽取欄位」的程式碼時，先把該筆紀錄的全部鍵印出來看過一遍，不要憑欄位名的直覺去猜。
- [L35・重掃最終產物會得到假陽性，因為剔除標記已經被移除了](lessons/L35-重掃最終產物會得到假.md) — 要獨立驗證掃描有沒有作用，做兩件事而不是重掃：一、牙齒測試 —— 把劇透版餵進同一支掃描函式，應該大量命中；回傳 0 才是壞了。
- [L36・重建與追加各自漏掉相反的一半](lessons/L36-重建與追加各自漏掉相.md) — 重建仍然是對的預設，因為它讓產出等於來源，不會有無聲的分岔。
- [L37・不要憑記憶補寫消失的來源](lessons/L37-不要憑記憶補寫消失的.md) — 純搬運的角色，產出的每一個字都要能指回一個現存的來源檔。
- [L38・被 hook 擋下時，正確的下一步是換人跑，不是找路](lessons/L38-被hook擋下時正確.md) — 被擋時先問「誰本來就有權限做這件事」，把檔名交給他，而不是想辦法讓自己通過。
- [L39・自然實驗裡兩個效應會纏在一起，指出混淆因子是你的職責](lessons/L39-自然實驗裡兩個效應會.md) — 你是唯一同時看得到全部資料與全部時序的人，所以混淆因子由你指出。
- [L40・判準寫錯的檢查，會用「通過」的樣子通過](lessons/L40-判準寫錯的檢查會用通.md) — 檢查通過時，回頭讀一次判準的文字敘述，問它跟你的實作是不是同一件事。
- [L41・記在記憶裡的盲訊號基準，會跨局變成假警報](lessons/L41-記在記憶裡的盲訊號基.md) — 任何跨局保留的基準，都要問「它在下一局開頭是不是還成立」。
