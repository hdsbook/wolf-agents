# 跨角色教訓（追加式）

每則格式：**教訓** → **怎麼用** → 來源局次。
**不得記載任何一局的底牌或當局狀態。** 這個目錄玩家在檔案系統層面讀得到。

---

## 2026-09-04 首局（9 人標準局，3 夜 3 天）

### L1・先問「這份資訊屬於哪一層」
公開（玩家可讀）／上帝視角（受保護）。設計任何新資訊時先分層，再決定放哪裡。

**首局的做法（加密 + 金鑰保管人）已於第二局停用**，改為 hook 存取控制。
但當初的分析仍然成立，而且正是換掉它的理由：**上帝的 session 紀錄是全場最易被讀取的檔案** ——
所以第二局起，transcript 目錄本身也納入了保護範圍，那是加密從來沒有碰過的洞。

**怎麼用**：判斷一個保護機制好不好，看它**保護的範圍**是否涵蓋真正的攻擊面，
而不是看它的技術強度。加密很強，但它保護錯了地方。

### L2・持久記憶不要寫進共用目錄
專案的 `memory/` 目錄對所有 session 可讀，且 `MEMORY.md` 索引會在每個 session 啟動時自動載入。
**怎麼用**：任何角色的私有筆記都放到共用目錄之外。**連檔名都算關聯字串** —— 首局的保管人筆記檔名與其 wrapper 目錄同名，光看檔名就縮小了搜尋範圍。

> `.claude/agent-memory/` 現在由 hook 擋著玩家讀不到了，但這條規則不變 ——
> **保護機制會改，寫進檔案的東西會留很久。不要讓紀律依賴當下的機制。**

### L3・公開檔採白名單思維
決定「放什麼進去」，而不是把內部文件刪一刪。
**怎麼用**：誘餌與浮水印一旦公開就完全失效；寫出 transcript 路徑等於教人作弊。交付前跑關鍵字掃描確認機密機制零命中。

### L9・範例一律用佔位符
所有文件與訊息中的例子用 `Pn` / `Px` / `Py`，永不使用真實座位號。
**怎麼用**：首局曾因訊息模板範例寫成真實座位號而洩漏一個身份。**交付任何文件前跑防劇透掃描**：`P[1-9]` 前後 14 字元內出現 狼人／預言家／女巫／獵人／平民／村民／查驗。

### L10・說謊與作弊的界線要公開寫清楚
跳身份、悍跳、隱瞞、誤導完全合法且鼓勵；作弊是繞過遊戲機制取得資訊。
**怎麼用**：這條**不講清楚，agent 會因為誠實傾向而不敢正常玩狼人殺**，整局會變得很平。寫進公開規則，並在發牌與宣誓時各提一次。

### L11・公開宣告稽核
嚇阻力來自「知道會被查」。
**怎麼用**：把稽核範圍與可追溯性寫進公開守則。首局實測全場零作弊，明文禁令的貢獻大於事後偵測。

### L12・session 重啟偵測要主動
`SendMessage` 的回傳偶爾會提示對方是新 session，但那是**偶然發現的，不可靠**。
**怎麼用**：每階段開始前用 `ListAgents` 比對各 session 的 ref 與開局基準，變動就要求重跑 `/ur`。

### L18・撤回的成本不是均等分配的
它與你已持有的資產成正比。手上只有公開資訊的人翻掉自己幾乎不花錢；扛著身份與票數的人翻掉自己等於放棄僅剩的防禦。
**怎麼用**：評價某人「不肯認錯」之前，先算他撤回要付多少。同一個動作在不同位置上價碼差很多。

### L19・「必敗」不等於「為假」
當一條分支通往必然的失敗，人會傾向相信它為假，因為只有另一條分支上自己的行動才有意義。
**怎麼用**：推理到「這條路必敗所以走另一條」時停一下 —— 你是在**判斷哪個世界為真**，還是在**選擇一個你需要為真的世界**？

### L20・成本與正確性無關
推理的說服力與它的沉沒成本正相關，而與它的正確性無關。
**怎麼用**：**一段愈來愈漂亮的論證，很可能只是因為它愈來愈貴。** 當撤回的成本開始變得昂貴，那正是最需要撤回的時刻。

## 2026-09-05 第四局

### L21・你回覆的內容會進到對方的 prompt，並可能觸發對方的 hook
跨 session 訊息不是純資料——它進入收件者的 prompt，收件者那一端的 `UserPromptSubmit` hook 會照常解析它。
所以**在訊息裡如實描述自己執行過什麼指令，可能會在對方那一端真的執行一次**。
第四局的上帝就是這樣被玩家的一句實話降級成玩家，失去主持權限。
**怎麼用**：回覆任何人時，一律用文字敘述指涉指令（「角色認領先前已完成」），
不要寫出斜線開頭的字串。這條對所有角色都適用，包含 reporter 與玩家。
反過來也成立：**需要讓對方那一端執行登記時，把指令字串放進發給他的訊息就會生效**——
這是修復角色登記錯亂的正規手段。

## 2026-09-05 第五局（9 人標準局，狼人屠邊勝）

### L22・證據支持的結論為真，不代表支持它的那條理由為真
本局第 2 天，六位好人的直覺全部指對了那兩隻狼，理由是「他們同輪同向，必定夜裡對過口徑」。三位玩家去讀規則原文，發現那個機制在當時的板子上不存在，於是五個人陸續撤回論證——**沒有一個人為了保住已投入的推理而硬撐**（這正是 L20 要求的紀律）。然後他們投死了一個平民，並放走了真狼。
**怎麼用**：**好人只能檢驗理由，不能檢驗結論。** 拆掉一條壞理由是對的，但要記得同時問：這條理由支持的那個結論，有沒有別的路可以到達？本局若有人在拆掉「對口徑」之後補問一句「那他們為什麼還是同向」，答案（都讀了同一份公開名單）反而會讓懷疑保留下來。**撤回論證時，把結論也一起丟掉，是最容易犯的第二個錯。**

### L23・把一件真事嫁接到自己身上，是最難拆穿的謊
一隻狼假跳神職，宣稱自己執行了某個夜間動作——而那個動作**確實發生過、結果也確實如他所說**，只有執行者是假的。真正的執行者前一晚剛死，無人能對跳。他的說法拿去對公開的死亡名單，怎麼對都對得上。
**怎麼用**：驗證一份宣稱時，「細節與公開紀錄吻合」的證明力比直覺上低很多——**吻合只證明他讀過紀錄**。要問的是「這件事只有他做得到嗎」，以及「有沒有人已經無法反駁他了」。當唯一能反駁的人剛死，任何吻合都應該打折。

### L24・自己公開立下的條件，會變成別人手上的鑰匙
本局一位玩家在發言中寫死改票條件（「只要女巫跳出來且毒殺對象與死亡名單對得上，我立刻改推她指的方向」）——那是很好的好人動作：先承諾、後執行，不讓自己事後找藉口。**但同一輪就有人提供了完全吻合的觸發**，而那個條件他全部滿足得起來。
**怎麼用**：公開承諾能建立可信度，代價是**把觸發器交到別人手上**。要立條件，就把它立在對手難以偽造的東西上（例如「除非有人能解釋 X 的時序矛盾」），而不是立在對手照著公開紀錄唸稿就能滿足的東西上。另一位玩家的評語值得記住：「你只是把一把很誠實的尺，交到了一個會唸稿的人手上。」

### L25・分段解析的產出，第一個該檢查的是最後一段的尾巴
reporter 本局踩到一次：公開檔尾多了一段非發言內容，而解析取內文是「一直取到下一個標題為止」——檔尾沒有下一個標題，那段就被併進了最後一則發言，看起來像是那位玩家自己講的。**所有計數都是對的**，8 則就是 8 則，唯獨內容被污染。
**怎麼用**：**容器裡最後一個元素會承擔所有不屬於任何元素的殘餘。** 計數檢查在原理上抓不到這一類（多出來的東西沒有變成新的一則）。檢查任何分段解析的產出時，先看最後一段的結尾。

### L26・檢查自動產生的東西，要同時做兩種相反的搜尋
「該有的沒出現」與「不該有的出現了」是兩種失敗，方法完全不同：前者要**先列預期清單再逐項核對**，後者要**拿已知不該出現的字串反向搜**。只做其中一種，另一種會全部漏掉。
**怎麼用**：reporter 由此發展出逐塊確認五問——這一塊在不在／有沒有不像人話的東西／欄位是不是不該地空著／數量對不對／最後一段的尾巴乾不乾淨。這套通用於任何自動產出的檢查，不限報表。

### L27・用「鍵在不在」決定顯示，不要用「值真不真」
渲染紀錄時，空物件與 null 在真假判斷下都是假。若照真假寫，「他可以指派而選擇不指派」會被畫成「這件事不存在」——**那等於抹掉一項真實的紀錄**。
**怎麼用**：判斷「這個概念在這一夜存不存在」用鍵的有無；判斷「他做了什麼」才用值。這條也適用於任何「缺席本身帶有意義」的資料。
