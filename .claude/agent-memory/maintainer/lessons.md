### M13・合併流程步驟時，先問「編號可以不動嗎」
把兩個步驟合併成一個，直覺是重編後面所有編號。但這個專案的步驟編號被寫死在
至少五個檔案裡（流程 skill 自己、上帝的編排參考、紀錄時機表、歸檔 skill、角色認領
skill），重編一次等於製造五處規格漂移的機會。

實際做法：合併時**把新內容塞進既有編號的位置**，讓小節數量不變。
這次是把「reporter 通訊測試」留在原本的第 5 步、「寫檔」留在第 6 步，
於是 0-13 全部原地不動，全庫交叉引用零改動 —— 驗證只要確認每個被引用的編號
指向的內容還對，不必逐一改寫。

**怎麼用**：改流程結構前先 `grep "第 [0-9]* 步"` 數一下有多少外部引用。
引用多的時候，**維持編號比讓編號好看更重要**。編號只是位址，
位址穩定的價值遠高於它讀起來連不連貫。

### M14・工作區的檔案會在你沒動它的時候被清空
這次提交前例行看 `git status`，發現自己的 lessons.md 被截斷成只剩標頭，
M1-M12 全部消失 —— 而我整場沒有寫過那個檔案。HEAD 版本完好，`git checkout --`
一行就還原了。

這是 M8「不要累積在工作區」的另一面：**已提交的東西活得下來，工作區的不一定。**
差別在於這次不是我自己弄丟的，所以更容易漏看 —— 沒有任何一步會提醒你。

**怎麼用**：`git add` 之前完整看一次 `git status --short`，
**對不是自己改的檔案也要看一眼 `git diff --stat`**。純刪除（`145 -----`、0 插入）
是最值得停下來的形狀。還原前先確認工作區那份沒有獨有內容，確認了再 checkout。
