# M22・換解析器時最強的測試是「同一份資料走兩條路徑」

**結論**：換解析器時最強的測試是「同一份資料走兩條路徑」

**原因**：`render.py` 改成優先讀 JSON、找不到才解析 Markdown 之後，怎麼證明沒改壞？
單看新路徑的產出「看起來對」證明不了什麼 —— 靜默內容遺失正是看起來對的。

做法是**讓同一份資料走兩次**：帶著 JSON 渲染一次存起來，把 JSON 刪掉再渲染一次，
兩份 HTML 逐行比對。相同就代表新路徑沒有多出、也沒有少掉任何東西。
再加一道：拿一份**歷史歸檔**（沒有 JSON）跑，與改動前的基準比對，
確認舊路徑零影響。兩道合起來，新舊都被釘住了。

**來源**：2026-09-06

**怎麼用**：任何「新增一條快速路徑、保留舊路徑當 fallback」的改動，
都要能建構出這種 A/B。建構不出來（例如兩條路徑吃的不是同一份資料），
那就代表它們其實不等價，**那才是真正要停下來的訊號**。
