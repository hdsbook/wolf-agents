# M23・工作要推到「已經擁有那份資訊的那一端」

**結論**：工作要推到「已經擁有那份資訊的那一端」

**原因**：上帝廣播時要生成九份幾乎相同的長訊息。我第一版的解法是「他渲染成檔案、玩家去讀」——
省掉了訊息本文，但他仍然要渲染九則指路訊息，而且那九則因為帶了收件人與檔名而各不相同。
**使用者指出真正的解法：他只送參數，訊息由玩家自己渲染。**

差別在於「誰做這件事最便宜」。渲染需要兩樣東西：模板與參數。
模板是固定的、九個人共用；參數是上帝手上的資料。
**玩家那一端本來就有模板（只要讓他讀得到），所以把渲染推過去，
上帝要傳的就只剩參數。** 實測 dawn 從 2568 字降到 612 字（剩 24%）。

而且它順帶解掉了一個我以為無解的限制：落檔方案受限於「檔案在公開區、全場都讀得到」，
所以含機密的訊息只能直送。**參數走的是點對點訊息，公開暴露的問題根本不存在。**

**來源**：2026-09-06

**怎麼用**：看到「同一件事重複 N 次、每次幾乎一樣」時，先問**變的是什麼**。
變的部分很小（這裡是座位號）就代表不變的那一大塊不該重複傳輸 ——
把它移到接收端，只傳變的部分。
