# M16・拆檔要「逐段對本文」，不是對行數或位元組

**結論**：拆檔要「逐段對本文」，不是對行數或位元組

**原因**：把一份大模板檔拆成七份時，最危險的失敗模式和改 `render.py` 一樣是**靜默內容遺失**。
行數、位元組、action 數量全部對得上，中間少一段照樣看不出來
（而且 CRLF→LF 會讓位元組數本來就對不上，見環境事實）。

實際做法：**用程式重建「拆檔前」的內容，切成 `{action: 本文}` 兩邊逐字比對**。
這次是 `git show HEAD:<檔>` 再套上我自己先前那一次編輯。
第一次跑就抓到一個差異 —— 結果是我**到之前就存在的未提交修改**，不是拆檔造成的。
那次「誤報」本身就是這個方法的價值：它逼我去確認差異的來源，而不是憑感覺放行。

**來源**：2026-09-06

**怎麼用**：任何搬運型改動（拆檔、合檔、換目錄）都先建立可比較的基準再動手。
基準必須是「改動前的同一份內容」；拿 HEAD 直接比會把別人未提交的修改誤判成你弄丟的東西。
