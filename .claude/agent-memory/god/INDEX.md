# 上帝的教訓（追加式）

每則一檔，格式：**結論** → **原因** → **來源** → **怎麼用**。
**絕不記載任何一局的底牌或當局狀態。**

**新增教訓**：在 `lessons/` 新增一檔，四欄格式（結論／原因／來源／怎麼用），並在本索引加一行。

## 2026-09-06

- [G-A・存活名單有三處，收尾時逐一點名](lessons/G-A-存活名單有三處收尾時.md) — 投票／夜間結算的收尾清單裡，把「三處存活名單」寫成三個檔名逐一勾，不要寫成一句「更新狀態檔」—— 抽象的那句話會讓你以為兩個就是全部。
- [G-B・一條驗不到東西的檢查，比沒有檢查危險](lessons/G-B-一條驗不到東西的檢查.md) — 任何自動檢查回報通過時，順手問一句「它這次實際讀到了幾筆」。
- [G-C・派下一位發言前，等的是「本人的落檔回報」，不是併檔端的回報](lessons/G-C-派下一位發言前等的是.md) — 必讀清單的權威來源只有一個 —— 玩家本人回報「已落檔」。
- [G-D・訊息裡「只有一小撮是機密」時，不要整則直送](lessons/G-D-訊息裡只有一小撮是機.md) — 要直送一則訊息之前，先問「這裡面哪幾個字是玩家不知道的」。
- [G-E・文件說「腳本會算」，要真的去驗它算不算](lessons/G-E-文件說腳本會算要真的.md) — 這是 G-B 的同一個形狀 —— 一條驗不到東西的檢查。
- [G-F・要驗玩家那一端跑不跑得動，就得真的找玩家跑](lessons/G-F-要驗玩家那一端跑不跑.md) — 改動任何玩家端的機制後，找一位玩家用假資料實測，並要求他回報「哪裡看不懂、哪裡資訊不足」。

- [G-I・稽核掃「收件人非上帝」時，要認得上帝的所有別名](lessons/G-I-稽核掃收件人非上帝時.md) — 開局記下上帝 session 的名稱與 ref，命中時先看內容是否為報到或對上帝的回覆再下結論。
