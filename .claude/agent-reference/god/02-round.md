# 工作流程：一輪對局

**情境**：開局已完成，正在跑第 N 天的循環。

## 編排

```
/god-night   夜間三階段 ──→ /god-day   天亮+發言 ──→ /god-vote  投票唱票
                                                          ↓
                              天數+1 ←── /god-audit  稽核 ←┘
```

分出勝負時，`/god-day` 或 `/god-vote` 會直接轉向 `/god-endgame`。

## 每階段開始前：檢查 session

用 `ListAgents` 比對各 ref 與 `02-status.md` 的基準。
**ref 變動 → 該 session 重啟過** → 走 `06-incident.md` 的重啟處理。

## 每階段結束後：固定四件事

1. 更新 `02-status.md` —— 天數、存活、剛完成什麼、**下一步是什麼**
2. 追加 `01-timeline.md`
3. 更新 `secret/*.json`（直接寫，無加解密）
4. 中立性自我稽核 → 向使用者回報 → 依節奏參數決定是否暫停（見下面兩節）

**第 3 項最容易漏。** 判準：剛剛有任何機密狀態改變嗎？有就封存。

## 依節奏參數決定是否暫停

**「暫停」＝結束你的回合，等使用者的下一則訊息。**
**回報不等於暫停** —— 三種設定你都照常回報每個階段發生了什麼，
差別只在回報完要不要停下來等他。

| 參數值 | 停在哪裡 |
|---|---|
| 每階段暫停 | 每個階段回報之後都停 |
| 每天暫停 | 只在投票結算後（一天結束）停一次；一天之內的階段不停 |
| **全自動到結局** | **不停**，一路跑到分出勝負 |

**不受這個參數影響的暫停點只有一個**：`/god-open` 第 13 步，進第一夜之前。
三種設定都照停 —— 那是最後一個「發錯牌還來得及重來」的檢查點。

## 你會在哪些地方讓出回合

除了上面那些暫停點，你只在**等一則一定會送來的訊息**時結束回合：

| 你在等什麼 | 誰會把你喚醒 |
|---|---|
| 開局的報到 | 玩家與 reporter 載入完會自己來 |
| 玩家的夜間行動、發言落檔回報、投票 | 他們一定會回 |
| 參數卡片、「天黑請閉眼」這類選項的答覆 | 使用者會回 |

**這張表以外的地方一律繼續跑，在同一個回合裡做下一步。**

兩個最容易誤停的位置：

- **剛把指派送給 reporter** —— 它依自己的紀律不回你（`agents/reporter.md`：
  只在發現問題時才出聲）。你在這裡停，**沒有任何東西會把你喚醒**。
- **剛寫完檔案、剛更新狀態檔** —— 那不是等待，那是你自己的工作做完了。

判準一句話：**你正在等某個人送訊息給你，才可以停；
只是「這一步做完了」，不可以。**

> 「不等它回覆」跟「不要結束回合」是兩件不同的事，前者不蘊含後者。
> 你可以完全不等 reporter，卻仍然因為「這一步做完了」而讓出回合。

## 一輪之內的資訊流

| 階段 | 誰知道什麼 |
|---|---|
| 夜間 | 只有行動者知道自己做了什麼；你知道全部 |
| 天亮 | 全場知道**誰死了**，不知道死因與身份 |
| 發言 | 逐字稿對後發言者公開，即時落地成公開檔 |
| 投票 | 唱票後**票型與所有理由全部公開** |

**票是最誠實的證據**，所以理由必須原文公開 —— 那是玩家隔天推理的主要素材。

## 什麼時候該懷疑自己跑錯了

- 存活人數與 `02-status.md` 對不上 → 停下來重算
- 票數總和 ≠ 存活人數 → 有人漏投或重複計算
- 角色數不是 3/3/1/1/1 → 底牌被改壞了，讀 `secret/roles.json` 核對
- reporter 通報一致性檢查未過 → **停下，不要繼續推進**，先查那一項
