# 工作流程：一輪對局

**情境**：開局已完成，正在跑第 N 天的循環。

## 編排

```
/god-night   夜間三階段 ──→ /god-day   天亮+發言 ──→ /god-vote  投票唱票
                                                          ↓
                              天數+1 ←── /god-audit  稽核 ←┘
```

分出勝負時，`/god-day` 或 `/god-vote` 會直接轉向 `/god-endgame`。

## 每階段開始前：檢查 session

用 `ListAgents` 比對各 ref 與 `02-status.md` 的基準。
**ref 變動 → 該 session 重啟過** → 走 `06-incident.md` 的重啟處理。

## 每階段結束後：固定四件事

1. 更新 `02-status.md` —— 天數、存活、剛完成什麼、**下一步是什麼**
2. 追加 `01-timeline.md`
3. 更新 `secret/*.json`（直接寫，無加解密）
4. 中立性自我稽核 → 向使用者回報 → 依節奏參數決定是否暫停（見下一節）

**第 3 項最容易漏。** 判準：剛剛有任何機密狀態改變嗎？有就封存。

## 節奏參數的操作定義

使用者在 `/god-open` 第 3 步選的「推進節奏」，具體代表這些行為：

| 參數值 | 你要做什麼 |
|---|---|
| 每階段暫停 | 每個階段結束、向使用者回報之後，停下來等他 |
| 每天暫停 | 只在**一天結束**（投票結算後）停一次；一天之內的階段不停 |
| **全自動到結局** | **完全不為使用者停**，一路跑到分出勝負為止 |

**「全自動到結局」的意思就是字面上那樣。** 你仍然照常向使用者回報每個階段
發生了什麼 —— 回報不等於暫停。回報完就繼續跑下一個階段。

唯一的例外是 `/god-open` 第 13 步那一次暫停：**三種設定都照停**。
理由寫在該處 —— 那是最後一個「發錯牌還來得及重來」的檢查點。

## 什麼時候才可以結束你的回合

這一節解決一個實際發生過的故障：**GOD 停在階段之間不動，外觀上像在等 reporter。**

規則只有一條：

> **回合結束的唯一合法理由，是你正在等一則一定會送來的訊息。**

| 情況 | 可以結束回合嗎 |
|---|---|
| 開局時等玩家與 reporter 陸續報到 | **可以** —— 他們一定會來，每一則報到都會把你喚醒 |
| 等玩家的夜間行動／發言落檔回報／投票 | **可以** —— 他們一定會回，回覆會把你喚醒 |
| 節奏參數要求在這裡暫停等使用者 | **可以** —— 使用者的下一則訊息會把你喚醒 |
| 剛送出給 reporter 的指派 | **不可以** |
| 剛寫完檔案、剛更新狀態檔 | **不可以** |

後兩項為什麼不可以：**那不是等待，那是你自己的工作做完了。**
而 reporter 依它自己的紀律**不會回你**（`agents/reporter.md`：只在發現問題時才出聲）——
所以你若在那裡讓出回合，就**沒有任何東西會把你喚醒**。

**沉默不會喚醒任何人。** 送完給 reporter 之後，**必須在同一個回合內繼續下一步**。

> 「不等它回覆」跟「不要結束回合」是兩件不同的事，前者不蘊含後者。
> 你可以完全不等它，卻仍然因為「這一步做完了」而讓出回合 —— 那就卡住了。

## 回報節奏的決策樹

```
現在是第幾夜？
├─ 第 1 夜 → 可依使用者的節奏參數逐階段回報
└─ 第 2 夜以後 → 夜間三階段一次跑完才回報
                  並向使用者說明這是刻意合併
```

**理由：階段的有無本身就是情報。** 預言家死後若逐階段回報，「今晚沒有查驗階段」就洩漏了他已出局。

白天不受此限 —— 發言輪與投票對所有人都是公開的。

## 一輪之內的資訊流

| 階段 | 誰知道什麼 |
|---|---|
| 夜間 | 只有行動者知道自己做了什麼；你知道全部 |
| 天亮 | 全場知道**誰死了**，不知道死因與身份 |
| 發言 | 逐字稿對後發言者公開，即時落地成公開檔 |
| 投票 | 唱票後**票型與所有理由全部公開** |

**票是最誠實的證據**，所以理由必須原文公開 —— 那是玩家隔天推理的主要素材。

## 什麼時候該懷疑自己跑錯了

- 存活人數與 `02-status.md` 對不上 → 停下來重算
- 票數總和 ≠ 存活人數 → 有人漏投或重複計算
- 角色數不是 3/3/1/1/1 → 底牌被改壞了，讀 `secret/roles.json` 核對
- reporter 通報一致性檢查未過 → **停下，不要繼續推進**，先查那一項
