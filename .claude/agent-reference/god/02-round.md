# 工作流程：一輪對局

**情境**：開局已完成，正在跑第 N 天的循環。

## 編排

```
/god-night   夜間三階段 ──→ /god-day   天亮+發言 ──→ /god-vote  投票唱票
                                                          ↓
                              天數+1 ←── /god-audit  稽核 ←┘
```

分出勝負時，`/god-day` 或 `/god-vote` 會直接轉向 `/god-endgame`。

## 每階段開始前：檢查 session

用 `ListAgents` 比對各 ref 與 `02-status.md` 的基準。
**ref 變動 → 該 session 重啟過** → 走 `06-incident.md` 的重啟處理。

## 每階段結束後：固定四件事

1. 更新 `02-status.md` —— 天數、存活、剛完成什麼、**下一步是什麼**
2. 追加 `01-timeline.md`
3. 更新 `secret/*.json`（直接寫，無加解密）
4. 中立性自我稽核 → 向使用者回報 → 依節奏參數決定是否暫停
   （暫停點與回合邊界見 `04-reporting.md`「依節奏參數決定是否暫停」）

**第 3 項最容易漏。** 判準：剛剛有任何機密狀態改變嗎？有就封存。

## 一輪之內的資訊流

| 階段 | 誰知道什麼 |
|---|---|
| 夜間 | 只有行動者知道自己做了什麼；你知道全部 |
| 天亮 | 全場知道**誰死了**，不知道死因與身份 |
| 發言 | 逐字稿對後發言者公開，即時落地成公開檔 |
| 投票 | 唱票後**票型與所有理由全部公開** |

**票是最誠實的證據**，所以理由必須原文公開 —— 那是玩家隔天推理的主要素材。

## 什麼時候該懷疑自己跑錯了

- 存活人數與 `02-status.md` 對不上 → 停下來重算
- 票數總和 ≠ 存活人數 → 有人漏投或重複計算
- 角色數不是 3/3/1/1/1 → 底牌被改壞了，讀 `secret/roles.json` 核對
- reporter 通報一致性檢查未過 → **停下，不要繼續推進**，先查那一項
