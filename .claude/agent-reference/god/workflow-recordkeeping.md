# 工作流程：狀態與檔案管理

**情境**：任何時候。這是貫穿全場的背景工作。

## 核心原則

**檔案是唯一真相來源，你的記憶只是快取。**

一局要跑 5~7 天、每天 15~20 次訊息往返，你的上下文一定會被壓縮。若狀態只活在記憶裡，壓縮後就會出現「忘記誰死了」「忘記女巫藥用掉沒」這類致命錯誤。

**每次狀態變動立刻落地。**

---

## 檔案分工

```
game-state/
├── public/     明文，玩家與使用者都可讀，且不會劇透
│   ├── HOSTING-PROCEDURE.md   規則副本
│   ├── 00-players.md          座位、暱稱、結局
│   ├── 01-timeline.md         每階段公開播報流水帳（追加式）
│   ├── 02-status.md           ★ 每階段覆寫，見下
│   ├── 03-speeches-dayN.md    發言逐字稿（每位講完即時追加）
│   ├── 04-votes-dayN.md       票型與所有投票理由
│   └── 99-reveal/audit/mvp.md 終局才寫
├── secret/     上帝視角，hook 保護（只有你與 reporter 讀得到）
│   ├── roles.json          底牌與浮水印
│   ├── nightlog.json       ★ 累積式，見下
│   ├── potions.json        藥水、獵人開槍、存活/死亡名單
│   └── report-spoiler.html reporter 產出，你不要動它
└── report/     reporter 的公開版 HTML，你不要動它
```

歷屆對局在 `../game-archive/`，全部公開。**這一局結束後由 `/god-archive` 搬過去。**

---

## `02-status.md` 是最關鍵的一份

**它是你失憶後唯一的入口。** 每階段覆寫，必須包含：

- 天數與當前階段
- 存活名單、死亡名單
- **剛完成什麼**
- **下一步要做什麼**（具體到該呼叫哪個 skill）
- 四個開局參數
- 11 個 session 的 ref 基準
- 已公開的身份宣告（玩家自述，你不確認也不否認）

**如果它過期了，代表你沒有遵守「每階段更新」的規則。**

---

## `nightlog` 必須是累積式

```json
{
  "nights":     [ {night:1,...}, {night:2,...}, {night:3,...} ],
  "day_votes":  [ {day:1,...}, {day:2,...} ],
  "hunter_declaration": {...},
  "current": {...}
}
```

**不可用單夜資料整份覆寫。**

> 上一局每晚都整份覆寫，吃掉了前兩夜的詳細紀錄，而**你自己完全沒察覺** ——
> 因為你知道全部真相，讀殘缺的紀錄仍然看得懂，缺的部分在你腦子裡。
> 是一個只有檔案、沒有記憶的角色發現的。
>
> **正確做法**：讀出整份 JSON → 在陣列末端 append 一筆 → 整份寫回。
> 絕對不要用單夜資料組一個新物件寫進去。

---

## 什麼時候寫 secret/

**判準：剛剛有任何上帝視角狀態改變嗎？**

| 事件 | 要更新什麼 |
|---|---|
| 開局洗牌後 | `roles.json` + `potions.json` |
| 每個夜間階段結束 | `nightlog.json`（append 一夜）+ `potions.json` |
| 天亮結算後 | `potions.json`（存活/死亡變動） |
| 投票結算後 | `nightlog.json`（append 一筆 day_votes）+ `potions.json` |

**直接讀寫 JSON，沒有加解密步驟。** 你通得過 hook 是因為你的 session 登記為 `god`。

## 什麼時候通知 reporter

只有兩個時機：**天亮結算後**、**投票結算後**。其他時候不必打擾它。

它會回報七項一致性檢查。**任何一項沒過就停下來先查** —— 那表示紀錄本身壞了，
繼續推進只會讓錯誤擴散到後面每一天。

---

## 公開檔的寫入時機

| 檔案 | 何時寫 |
|---|---|
| `01-timeline.md` | 每階段結束追加 |
| `02-status.md` | 每階段結束覆寫 |
| `03-speeches-dayN.md` | **每位玩家講完立即追加**，不要等整輪結束 |
| `04-votes-dayN.md` | 唱票後 |

發言逐字稿要即時寫，因為後面的玩家可能被指向這個檔案自己讀 —— **它必須隨時是最新的**。

---

## 防劇透紀律

`public/` 的語意是「對局中玩家可讀的範圍」。

- **不要把夜間原始資料放進 `public/`**，即使終局後也不要 —— 那會破壞它作為紀錄的一致性。解密的東西放 `archive/`。
- 任何要寫進公開檔的內容，**交付前跑防劇透掃描**：`P[1-9]` 前後 14 字元內出現 狼人／預言家／女巫／獵人／平民／村民／查驗。
- **範例一律用 `Pn` / `Px` / `Py` 佔位符**，永不使用真實座位號。

> 上一局曾因訊息模板範例寫成真實座位號而洩漏一個身份給使用者。
