# 工作流程：狀態與檔案管理

**情境**：任何時候。這是貫穿全場的背景工作。

## 速覽

| 主題 | 關鍵守則 | 產出／檔案 |
|---|---|---|
| 核心原則 | 檔案是唯一真相來源，每次狀態變動立刻落地 | — |
| `02-status.md` | 每階段覆寫，失憶後唯一的入口 | `public/02-status.md` |
| `nightlog` | 累積式：讀出 → append → 寫回，絕不整份覆寫 | `secret/nightlog.json` |
| 寫 `secret/` | 有上帝視角狀態改變就寫；`result` 勝負真的達成才寫 | `secret/*.json` |
| 落檔點與 reporter 指派 | **唯一來源**；結果未公告前只產劇透版 | 見該節對照表 |
| 公開檔寫入時機 | 逐字稿不由你寫 | `01`／`02`／`04` |
| 防劇透 | 範例一律用佔位符 | — |

## 核心原則

**檔案是唯一真相來源，你的記憶只是快取。**

一局要跑 5~7 天、每天 15~20 次訊息往返，上下文可能會被壓縮。若狀態只活在記憶裡，壓縮後就會出現「忘記誰死了」「忘記女巫藥用掉沒」這類致命錯誤。

**每次狀態變動立刻落地。**

## 檔案分工

```
game-state/
├── public/     明文，玩家與使用者都可讀，且不會劇透
│   ├── HOSTING-PROCEDURE/     規則副本（目錄，`.claude/rules/` 六份）
│   ├── mailbox/               公版訊息的參數（目錄）—— 玩家自己渲染訊息用
│   │                          `<tag>/params.json`，tag 帶階段避免渲染出上一輪
│   ├── 00-players.md          座位、結局
│   ├── 01-timeline.md         每階段公開播報流水帳（追加式）
│   ├── 02-status.md           ★ 每階段覆寫，見下
│   ├── speech-inbox/          ★ 玩家自寫的發言原文，一人一檔（你不寫、不改）
│   ├── 03-speeches-dayN.md    正式逐字稿（由 /reporter-collect 併檔產生）
│   ├── 04-votes-dayN.md       票型與所有投票理由
│   └── 99-reveal/audit/mvp.md 終局才寫
├── secret/     上帝視角，hook 保護（只有你與 reporter 讀得到）
│   ├── roles.json          底牌與浮水印
│   ├── nightlog.json       ★ 累積式，見下
│   ├── potions.json        藥水、獵人開槍、存活/死亡名單
│   └── report-spoiler.html reporter 產出，你不要動它
└── report/     reporter 的公開版 HTML，你不要動它
```

歷屆對局在 `../game-archive/`，全部公開。**這一局結束後由 `/god-archive` 搬過去。**

## `02-status.md` 是最關鍵的一份

**它是你失憶後唯一的入口。** 每階段覆寫，必須包含：

- 天數與當前階段
- 存活名單、死亡名單
- **剛完成什麼**
- **下一步要做什麼**（具體到該呼叫哪個 skill）
- 三個開局參數
- 11 個 session 的 ref 基準
- 已公開的身份宣告（玩家自述，你不確認也不否認）

**如果它過期了，代表你沒有遵守「每階段更新」的規則。**

### 身份宣告那一節的格式

```markdown
## 已公開的身份宣告

玩家自述，上帝不確認也不否認。原樣轉錄自逐字稿標題。

| 座位 | 宣告 | 首次於 |
|---|---|---|
| Px | 預言家 | D2 |
| Py | 不表態 → 神職 | D1 → D2 |
```

「宣告」欄只寫玩家自己填的那個 token，改口的用 `→` 串起來，兩個天數都列。
「首次於」寫 `D<天>`，PK 發言寫 `D<天>PK`。

**這是純搬運。** 來源是 `03-speeches-dayN.md` 的標題標記，不是你讀完發言後的歸納 ——
判讀誰跳了什麼會違反 `god-neutrality.md`。

> `render.py` **不讀這個檔**，報表的宣告標籤直接解析逐字稿標題。
> 兩處若不一致，**以逐字稿為準** —— 這一節服務的是「你失憶後接續主持」。

## `nightlog` 必須是累積式

```json
{
  "nights":     [ {night:1,...}, {night:2,...}, {night:3,...} ],
  "day_votes":  [ {day:1,...}, {day:2,...} ],
  "hunter_declaration": {...},
  "current": {...}
}
```

**不可用單夜資料整份覆寫。**

### 每一夜要記的狼隊欄位

```json
{
  "night": 1,
  "wolf_leader": "Px",
  "wolf_succession": ["Py", "Pz"],
  "succession_default": false,
  "wolf_signals": [
    {"seat": "Py", "signals": ["刀 Pn", "Pn 像預言家"]},
    {"seat": "Pz", "signals": []}
  ],
  "wolf_plan": {
    "kill": "Pn", "self_kill": false,
    "claim_seer": null, "claim_second": null,
    "hook": null, "deep": []
  }
}
```

`kill` 一定有值。**分工四欄允許 `null` 與空陣列** —— 隊長那一夜沒有指派就是沒有指派。

> **沒填的欄位要留 `null`，不要整個省略掉。** 省略之後，日後回頭看分不出
> 「問過但他選擇不指派」與「這一夜根本沒有這個機制」—— 前者是戰術判斷，
> 後者是紀錄缺漏，兩者的意義完全不同。

> `succession_default` 為 `true` 表示隊長沒交接班順位、由你依座位號補的。
> 這一欄的用途是**事後分辨那個順位是他的決定還是你的預設**。

> 逾時未交暗號的狼，`signals` 記空陣列，不要把他從 `wolf_signals` 拿掉 ——
> 「他在場但沒說話」跟「他不在場」是兩件事。

> 上一局每晚都整份覆寫，吃掉了前兩夜的詳細紀錄，而**你自己完全沒察覺** ——
> 因為你知道全部真相，讀殘缺的紀錄仍然看得懂，缺的部分在你腦子裡。
> 是一個只有檔案、沒有記憶的角色發現的。
>
> **正確做法**：讀出整份 JSON → 在陣列末端 append 一筆 → 整份寫回。
> 絕對不要用單夜資料組一個新物件寫進去。

## 什麼時候寫 secret/

**判準：剛剛有任何上帝視角狀態改變嗎？**

| 事件 | 要更新什麼 |
|---|---|
| 開局洗牌後 | `roles.json`（**你寫**）；`potions.json`（含 `"result": null`）與 `nightlog.json` 由 reporter 的 `/reporter-init` 建 |
| 每個夜間階段結束 | `nightlog.json`（append 一夜）+ `potions.json` |
| **天亮公告發出後** | `potions.json`（存活/死亡變動） |
| 投票結算後 | `nightlog.json`（append 一筆 day_votes）+ `potions.json` |
| **勝負達成時** | `potions.json` 的 `result` 欄位 |

> `result` 形如 `{"winner": "好人|狼人", "reason": "屠邊（平民全滅）", "day": 3}`，
> 是 `render.py` 判斷「公開版要不要揭底牌」的**唯一開關**。
> **勝負真的達成才寫** —— 提早寫入等於提早向全場公開底牌。

**直接讀寫 JSON，沒有加解密步驟。** 你通得過 hook 是因為你的 session 登記為 `god`。

## 落檔點與 reporter 指派

已移到 `.claude/agent-reference/shared/02-reporter-dispatch.md`（**唯一來源**；reporter 也要讀得到，所以不放在 god/）。

## 公開檔的寫入時機

| 檔案 | 何時寫 |
|---|---|
| `01-timeline.md` | 每階段結束追加 |
| `02-status.md` | 每階段結束覆寫（**含天亮公告後那一次** —— 不要拖到發言輪跑完） |
| `03-speeches-dayN.md` | **不由你寫。** 玩家寫進 `speech-inbox/`，reporter 用 `/reporter-collect` 併檔 |
| `04-votes-dayN.md` | 唱票後 |

發言逐字稿**不再是玩家取得資訊的路徑** —— 他們直接讀 `speech-inbox/` 的原文，
所以併檔落後幾位不影響對局。它服務的是報表輸入、歸檔與爭議時的引用。

> **你在發言輪不讀發言內容、不寫逐字稿、不整理票型指向。**
> 這三件事都是純搬運，卻各給了你一次接觸發言的機會 ——
> 上一局的偏袒就是從這種機會裡長出來的（G11）。移走搬運，機會就不存在。

> 曾有一局第 1 天，上帝在 `03-speeches-dayN.md` 末尾追加摘要，誤將一則具體身份判斷寫進公開檔案，
> 由玩家與 reporter 抓到（教訓 G11，查 `.claude/agent-memory/god/INDEX.md`）。
> **現在這個錯誤在結構上不可能發生了** —— 你不再是那份檔案的寫入者。

## 防劇透紀律

`public/` 的語意是「對局中玩家可讀的範圍」。

- **不要把夜間原始資料放進 `public/`**，即使終局後也不要 —— 那會破壞它作為紀錄的一致性。解密的東西放 `archive/`。
- 任何要寫進公開檔的內容，**交付前跑防劇透掃描**：`P[1-9]` 前後 14 字元內出現 狼人／預言家／女巫／獵人／平民／村民／查驗。
- **範例一律用 `Pn` / `Px` / `Py` 佔位符**，永不使用真實座位號。

> 上一局曾因訊息模板範例寫成真實座位號而洩漏一個身份給使用者。
