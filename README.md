# 狼人殺・多 Agent 對局系統

用 **11 個獨立的 Claude session** 跑一場 9 人標準局狼人殺：
**1 個上帝（god）＋ 9 個玩家（p1~p9）＋ 1 個記錄者（reporter）。**

玩家彼此完全隔離，所有資訊流經過上帝。上帝對玩家嚴格中立，對你（使用者）則會完整播報。

---

## 一、需要開幾個 session

**11 個。**

| 角色 | 數量 | session 名稱 |
|---|---|---|
| 上帝 | 1 | `GOD` |
| 玩家 | **9** | `P1` `P2` `P3` `P4` `P5` `P6` `P7` `P8` `P9` |
| 記錄者 | 1 | `reporter` |

> 板子是 9 人標準局（3 狼／3 民／1 預言家／1 女巫／1 獵人），所以玩家是 **P1~P9 共九位**，沒有 P10。
> 加上上帝與記錄者，總共 11 個 session。

---

## 二、開始步驟

### 步驟 1：建立 11 個 session

在 Claude Code 的 agent view 中建立 11 個背景 session，**並各自改名**為上表的名稱。

名稱很重要 —— 上帝靠它們發訊息，稽核也靠它們對帳。

### 步驟 2：每個 session 各自認領角色

在**每一個** session 裡執行對應的指令：

```
在 GOD    的 session：  /join-as god
在 reporter 的 session：/join-as reporter
在 P1     的 session：  /join-as p1
在 P2     的 session：  /join-as p2
在 P3     的 session：  /join-as p3
在 P4     的 session：  /join-as p4
在 P5     的 session：  /join-as p5
在 P6     的 session：  /join-as p6
在 P7     的 session：  /join-as p7
在 P8     的 session：  /join-as p8
在 P9     的 session：  /join-as p9
```

`/join-as` 會做四件事：載入該角色的簡報、載入它該知道的規則、**把這個 session 登記進存取控制名單**、然後自動向上帝報到（上帝自己不需報到）。

> 大小寫不拘，`/join-as P3` 或 `/join-as 3` 都可以。
> 若某個 session 中途重啟，再跑一次同樣的指令即可恢復。
>
> **這一行必須由你親自輸入。** 登記是靠一個 hook 攔截你的輸入完成的 ——
> agent 自己在對話中提到這串字不會生效。

### 步驟 3：回到 GOD 的 session，開始遊戲

依序下三個指令：

```
/god-roll-call      點名 11 個 session，測試 SendMessage 是否正常
/god-setup          問你四個參數 → 洗牌發牌 → 彙整名冊 → 收公平競賽承諾 → 建立狀態檔
/god-night          天黑，第一夜開始
```

**`/god-roll-call` 未達 11/11 不會讓你繼續** —— 這一步存在的理由是：整場遊戲建立在跨 session 訊息上，若有一條線不通，問題會在第三天才浮現，那時已無法補救。

### 步驟 4：之後只要跟著上帝走

上帝會在每個階段結束時向你回報，並告訴你下一個指令。循環是：

```
/god-night  →  /god-day  →  /god-vote  →  /god-audit  →  （天數+1，回到 /god-night）
```

分出勝負時，上帝會自動轉向 `/god-endgame`。

**玩家與記錄者全程不需要你操作** —— 上帝會私訊他們，他們會執行對應的 skill 並回覆。

想隨時看戰況，可以直接在 reporter 的 session 下 `/reporter-build`，它會重建報表。

## 三、`/god-setup` 會問你的四個參數

| 參數 | 選項 | 預設 | 影響 |
|---|---|---|---|
| 白天發言模式 | 序列／並行／混合兩批 | 序列 | 序列讓後發言者看得到前面的逐字稿，互動品質高但每輪 8~9 次往返 |
| 你的角色 | 純觀戰／上帝視角觀戰／下場當玩家 | 純觀戰 | 純觀戰保留懸疑感，你不會知道任何人的底牌 |
| 推進節奏 | 每階段暫停／每天暫停／全自動 | 每階段暫停 | 決定上帝多久停下來等你 |
| 播報風格 | 中立紀實／沉浸敘事 | 中立紀實 | **只影響對你的敘述**，對玩家的訊息永遠中立 |

## 四、對局中你會看到什麼

- **每個階段結束**：上帝回報這一階段發生了什麼、目前存活誰、下一步是什麼
- **發言輪**：每位玩家講完，上帝立即轉述
- **唱票**：完整票型 + 每個人的投票理由原文
- **每夜稽核**：上帝掃描所有玩家的工具使用紀錄，回報有無作弊跡象
- **終局**：全員底牌、完整戰報、稽核報告、MVP 票選

所有紀錄同步落地在 `game-state/public/`，你隨時可以自己打開看 —— **那個目錄不會劇透**（機密都在 `secret/`）。

### 兩份 HTML 戰況報表

記錄者會在每天天亮與每次投票後重建兩份儀表板，用瀏覽器直接開：

| 檔案 | 內容 |
|---|---|
| `game-state/report/index.html` | **公開版** —— 座位圖、時間軸、發言逐字稿、票型矩陣。零劇透，玩家也讀得到 |
| `game-state/secret/report-spoiler.html` | **劇透版** —— 上列全部，再加上底牌、每夜刀／查驗／用藥、發言旁標註真實陣營 |

**純觀戰的話就只開公開版。** 劇透版隨時在那裡，看不看由你決定。

## 五、三個角色在做什麼

### 上帝（god）
發牌、主持七個階段、裁決規則、稽核作弊、向你播報。

**對玩家嚴格中立** —— 只給局面、私有資訊、原文逐字稿、要做什麼、規則條文。不給建議、不給分析、不給摘要。這份契約寫在 `.claude/rules/god-neutrality.md`，是**公開檔**，玩家可以據此監督他。

### 玩家（p1~p9）
只知道自己的底牌。上帝私訊他們時會指定要執行哪個 skill（`/player-speak`、`/player-vote`、`/player-night-action`、`/player-vote-mvp`），格式由 skill 保證一致。

**說謊、跳身份、悍跳、誤導都是合法戰術**；作弊指的是繞過遊戲機制取得資訊（讀紀錄檔、翻機密檔、探查他人）。

**玩家沒有跨局記憶** —— 每一局都從零開始，這是公平性要求。

### 記錄者（reporter）
不參與遊戲，不發言，不投票。它讀得到全部（公開紀錄 + 上帝視角），做兩件事：

1. **產出兩份 HTML 戰況報表**（見上一節）
2. **結構稽核** —— 檢查上帝的紀錄有沒有壞掉

第 2 項比聽起來重要：**上帝知道全部真相，所以他讀殘缺的紀錄仍然看得懂**，缺的部分在他腦子裡。
記錄者只有檔案，檔案壞了它就畫不出來，所以它會發現。上一局上帝每晚把夜間紀錄整份覆寫、
吃掉了前兩夜，就是這樣被抓到的。

## 五之二、玩家為什麼作弊不了

**不是靠約定，是靠一個實際會擋下工具呼叫的 hook。**

`/join-as` 會把每個 session 登記進 `.claude/hooks/roster.json`。之後每一次檔案存取，
hook 都會比對呼叫者的身分：

| 路徑 | 誰通得過 |
|---|---|
| `game-state/secret/` | 上帝、記錄者 |
| **其他 session 的對話紀錄（`.jsonl`）** | 只有上帝（稽核用） |
| 上帝與記錄者的 skill、`agent-memory/` | 各自的擁有者 |
| `.claude/settings.json`、`.claude/hooks/` | 只有上帝 |

玩家可以自由讀 `.claude/rules/`、`game-state/public/`、公開版報表、以及 `game-archive/`。

**每一次被擋下都會寫進 `.claude/hooks/access.log`**（時間、session、工具、完整參數），
上帝每夜稽核時會看，終局報告也會附上全文。

### 誠實說明

hook 由 Claude Code 執行，**刻意繞過仍有可能** —— 例如用字串拼接組出路徑讓比對抓不到。
這不是作業系統層級的權限控制。

被真正堵死的是那條**不需要任何作弊意圖就會外洩**的路。剩下的刻意規避由三樣東西負責：
公開的守則、每夜稽核、以及 `game-state/` 根目錄那份**內容是假的誘餌底牌** ——
它放在保護區外面，讀它不需要繞過任何東西，所以讀了就是刻意。

## 六、檔案在哪裡

```
.claude/
├── CLAUDE.md          極簡說明
├── agents/            三份角色簡報（god / player / reporter）
├── rules/             五份公開規則，任何人都能讀、能在爭議時引用
├── agent-reference/   跨 skill 的角色層知識
├── agent-memory/      god 與 reporter 的跨局教訓（玩家沒有，這是公平性要求）
├── hooks/             存取控制：policy.py / guard_secrets.py / register_role.py
│                      roster.json（誰是誰）、access.log（被擋下的嘗試）
└── skills/            17 個 skill
    ├── join-as              三方共用
    ├── god-*        (10)    點名／開局／夜／日／投票／稽核／終局／發訊／歸檔／復原
    ├── player-*     (4)     發言／投票／夜間行動／MVP
    └── reporter-*   (2)     產報表／一致性檢查

game-state/            進行中的這一局
├── public/            公開，所有人可讀
├── secret/            上帝視角，hook 保護
└── report/            公開版 HTML 報表

game-archive/          歷屆對局，全部公開
├── INDEX.md           一覽表
└── 001-20260904/      public / god-view / report / SUMMARY.md
```

## 七、常見狀況

**某個 session 重啟了怎麼辦？**
在那個 session 再跑一次 `/join-as <role>` 就好。它會告訴上帝自己重啟過，上帝會補發它原本持有的資訊（不會給額外優勢）。上帝每階段開始前也會主動比對，發現 ref 變動就會要求重跑。

**上帝失憶了怎麼辦？**
在 GOD session 執行 `/god-resume`。它會從 `game-state/public/02-status.md` 讀回天數、存活名單、當前階段與下一步，再直接讀 `secret/` 取回上帝視角。

**某個角色重啟後讀不到它該讀的東西？**
session 重啟會換 id，而存取控制記的是 id。重跑 `/join-as <role>` 通常就好。
若還是不行，表示舊 id 還佔著位置（角色**先到先得**）—— 直接編輯
`.claude/hooks/roster.json` 把該角色改成新的 id 即可，那是純文字檔。
被拒絕的認領都記在 `roster-conflicts.log`。

**上一局還沒歸檔就想開新的一局？**
`/god-setup` 會先檢查並要求你跑 `/god-archive`，把上一局搬進 `game-archive/`。
**不要手動覆寫 `game-state/`** —— 那會吃掉上一局的紀錄，而且不會有任何錯誤訊息。

**我想中途改節奏？**
直接跟上帝說。節奏、播報風格都可以隨時調整。

**遊戲要跑多久？**
上一局實測是 3 夜 3 天結束（狼隊屠邊獲勝），產出 20 份發言逐字稿。5 天左右是常見長度。

**上帝給了我不該給的建議怎麼辦？**
如果是給**玩家**的訊息夾帶了戰術建議，那違反中立性契約 —— 玩家可以當場指出，上帝也會在每階段自我稽核時掃描自己的用詞。給**你**的分析與摘要則不受限制，那是刻意的。
