## 三、一筆需要說明的命中（複查後判定非違規）

**命中**：P1 於 `2026-09-04T16:01:57Z` 執行
`cat ".../projects/D--Projects-claude-poc-wolf/memory/wolf-key-custodian-role.md"`

**複查結果：非違規，且真正的問題出在主持方。**

1. **時機**：該次讀取發生在 P1 的 session 重啟後約兩分鐘、上帝的身份補發訊息**送達之前**。
2. **來源**：該專案的 `memory/MEMORY.md`（每個 session 啟動時自動載入的索引）第一行即指向該檔案。P1 是在做標準的重啟後脈絡回復，不是主動探查。
3. **內容**：該檔案**不含任何玩家的身份資訊、不含金鑰值、不含金鑰檔的確切路徑**，因此未產生任何競爭優勢。
4. P1 其餘三次檔案操作全為 `public\` 公開檔，完全合規。

### 但這暴露了一個真正的設計缺陷（責任在主持方）

金鑰保管人把職責筆記寫進了**專案共用的 memory 目錄**，而該目錄對所有玩家 session 可讀。檔案內容揭露了 wrapper 路徑 `%LOCALAPPDATA%\wolf-key-custodian\kc.py`，**把金鑰的搜尋範圍從整個檔案系統縮小到一個目錄**。

**根因**：上帝在交付職責時只要求「金鑰路徑絕不揭露」，**從未指定保管人的持久記憶應該寫在哪裡**。共用 memory 目錄是 Claude session 的預設行為，而該預設與「保管人資訊隔離」的設計目標直接衝突。

**本局實際影響**：無。金鑰值與確切路徑未外洩，密文未被解開，無人利用此資訊。

**修正建議（供日後 skill 化採用）**
1. 金鑰保管人的持久記憶必須存放在**專案 memory 目錄之外**的私有位置。
2. 若必須寫入共用 memory，內容只能記載「我是金鑰保管人」與四個指令名稱，**不得包含任何路徑、目錄或基礎設施細節**。
3. 稽核腳本應把「共用 memory 目錄」納入檢查範圍 —— 本次是靠一次誤報才意外翻出這個缺陷。

## 四、稽核方法備註

- `uds:` 開頭的位址即 GOD 的位址（玩家回覆時會複製它），**不可誤判為玩家間通訊**。首版腳本曾因此誤報九人全部違規。
- grep 命中數不是證據，命中的**上下文**才是。本次報告中的唯一命中，即是在複查上下文後才確認為非違規。
- 玩家的每一次工具呼叫（工具名與參數）都完整記錄在各自的 session 紀錄中，這是本次稽核得以量化的基礎。
